# 批量准备草稿

适用于把几篇本地文稿一起带入网站。每篇仍是独立文章：先扫描，再逐篇预览并确认创建。
本功能不更新已有文章、不自动发布，也不继承源文件绑定。

## 选择文稿

1. 在后台打开 **工具 → Markdown 编辑桥**，选择 **批量导入草稿**。
2. 选择最多 10 个 `.md`、`.markdown` 或单文稿 `.zip`，点击 **扫描所选文件**。
3. 每个 ZIP 沿用单篇图片导入格式：一篇 Markdown，加上文中相对路径引用的 PNG、JPEG、
   GIF 或 WebP 图片。现有便携导出清单可继续使用。ZIP 不是包含多篇正文的任意目录包。

每篇正文最多 256 KiB，单 ZIP 最多 8 MiB；整批上传最多 16 MiB，展开最多 32 MiB。
图片沿用既有类型、大小、路径和摘要校验；每项最多 64 MP、整批处理最多 128 MP，失败文件已经处理的像素也计入预算。ZIP 需要上传媒体权限及服务器 ZIP 依赖；
有写稿权限的贡献者可以批量准备普通 Markdown 草稿。

扫描只使用私有暂存，不创建文章或附件。结果逐项显示：

- 可预览：转换通过，可修改从文件名取得的默认标题。
- 需要修正文稿：例如缺图、不支持的区块、损坏 ZIP 或超出限制。修改原文件后重新准备。
- 重复提醒：同名文件、相同正文或已有可编辑文章使用相同标题／正文。提醒不代表这些是同一篇文章，确认仍然新建草稿。

已有网络图片 URL 只保留，不由服务器下载。Markdown 头部继续保存在原稿，但批量导入
不会应用其中的发布状态、标题、分类或其他元数据。文章标题使用本次逐篇确认的输入。
附件数字 ID 只表示原网站关系，不能由批次信任；请使用不含旧站 ID 的便携图片。

## 逐篇预览和创建

1. 在该文稿下调整标题，点击 **预览此项**。
2. 检查正文、公式、图片和原始 Markdown。预览不会创建附件；交互组件保持静态替代内容。
3. ZIP 含图片时，明确勾选媒体公开提示。WordPress 原始媒体 URL 可能公开，即使文章保持草稿。
4. 点击 **创建此草稿**。成功后使用 **打开已创建草稿**进入正常编辑器，继续编辑或按原流程发布。

修改标题会使旧预览失效，需要重新预览。每篇只在明确确认后创建；不会因为一篇成功就
自动导入后面的文稿。创建成功的草稿和附件不会因其他项失败而回滚。

## 断线、取消和继续

批次最多保留一小时，每个账号最多两个活动批次，站点另有 16 条暂存记录的共享上限。
关闭窗口不会取消服务器上已经开始的保存。重新打开功能，可恢复当前账号的活动批次；
重新登录后仍须重新鉴权，其他账号不能读取或继续该批次。

网络中断时先点击 **刷新批次状态**。系统用每项固定身份和同事务保存的来源凭据核验已
创建文章，重复确认不会再建一篇。如果无法证明上次保存结果，会显示 **保存需要核验**，
保留暂存并停止自动重试；此时先检查文章和媒体，不要重新导入同一项。

**取消剩余项目并移除暂存**只清理本批可验证归属的暂存，已经创建的草稿及媒体继续保留。
有不确定保存结果时会拒绝取消并保留暂存、占用原额度，避免丢掉核验依据；这类记录不会仅因一小时过去就被自动清理，需要管理员核实。过期后尚未创建的项目需要重新准备，
已创建草稿不受影响。过期清理在访问批次功能时执行，不新增后台定时任务。

原始文件仍由作者保管；私有暂存与进度不代替原稿、修订或备份。
