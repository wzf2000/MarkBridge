# 发行渠道与提交准备

本页适用于 MarkBridge 3.0.0 正式稳定版。主插件保持同一源码和安装 ZIP；WordPress.org 提交、GitHub Release 与生产部署是独立动作。

## 通用主包

作者从正式 Release 下载 `markbridge-<版本>.zip`，按普通 WordPress 上传插件流程安装。主包默认使用随包提供的 PHP 转换器；Node 仅供管理员准备并验证环境后明确选择。基础转换、公式和字体不依赖 CDN、在线安装器或外部执行服务。

构建只复制锁定 MathJax 的 CHTML 运行树、动态字形、字体及可读的相关字体模块；保留上游许可和来源说明。构建拒绝覆盖被人工修改或未登记的生成资源。安装包和发行验证都要求压缩 ZIP 小于 10,000,000 字节，并核对 CRC、版本、源码提交和精确文件清单。公开安装包不包含私有运行环境、来源映射、站点数据或独立更新器。

开发者可运行 `npm run package:source` 另生成可读源码附件，包含源码、锁文件、构建入口、测试和相关字体模块。它不是插件安装包；正式安装包仍从精确提交的干净 Git 检出构建，不绕过原有发行身份检查。字体原声明仓库不可用的事实见 [NOTICE](../NOTICE.md)，不把可读模块声称为已找到的原始 TypeScript 树。

## WordPress.org

主包没有外部更新钩子或 `Update URI`，保留 WordPress.org 原生更新机制。主插件尚未上架；提交前仍需维护者确认目录账号、插件名／slug、正式版本和实际测试范围，按平台要求填写贡献者等资料。包内 `Stable tag` 不代表已批准的稳定目录版本。

使用官方 Plugin Check 在独立 WordPress 上执行默认检查，保留完整报告并逐项处理。工具退出 0、模型通过或包大小合格都不等于平台审核通过。原子文件锁、绑定源文件身份、受控可选 Node 运行环境、原字节下载和内部诊断有各自安全合同，不能仅为消除静态告警而改变为有损转义、FTP 文件操作或取消保护。平台对这些用途及第三方源码披露的最终判断应随提交材料明确说明，不隐瞒剩余发现。

首次提交应附安装流程、支持范围、许可／源码、默认不进行外部网络通信、浏览器本地恢复和媒体公开性说明，以及固定候选的验证结果。人工审核与账号操作属于后续公开发布流程。

### 静态检查的处理范围

提交准备使用官方 Plugin Check 2.1.0 的默认检查，不排除规则。直接 Web 访问保护、上传字段类型验证、固定枚举输出转义及缺少 mbstring 时的诊断启动已修正。剩余发现须连同完整报告供人工审阅，不能将命令退出 0 称为检查全过。

| 发现类别                  | 实现合同与提交时需说明的事项                                                                                                                          |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 翻译 HTML、下载与内部异常 | 翻译的标签／属性形状固定且有双端正反例；下载需鉴权、原字节及 attachment／nosniff；内部诊断经 JSON／文本边界展示。不可统一 HTML 转义而破坏正文或协议。 |
| 文件系统操作              | 私有目录、有界读写、路径与来源核验、锁及原子替换共同保护已有文件；使用通用 FTP 文件层不能代替这些保证。                                               |
| 输入与 nonce              | 保存和设置有对象权限及 nonce／校验凭据；原始正文保持字节，读选择限闭合 ID。旧原生编辑兼容上下文仍依赖 WordPress 核心权限检查，需审阅实际调用链。      |
| 数据库与缓存              | 新鲜版本读取与事务协调故意避免旧缓存；不通过直接 SQL 更新文章正文。                                                                                   |
| 可选执行与翻译域加载      | 默认 PHP 不启动外部进程；Node 只在管理员配置并验证后运行受控转换环境。翻译域需兼容未上架安装和实际用户语言。                                          |

这些说明是提交审查材料，不是平台认可或对任意插件组合的安全保证。若平台要求改变上述架构，应另行评估兼容和保存保护，不通过关闭检查或删除诊断隐藏差异。

## 可选 GitHub 更新器

GitHub 更新采用独立的 `MarkBridge GitHub Updater` 插件，主包不附带、不下载、不自动启用。管理员先安装并启用主插件，再单独安装更新器，在 **设置 → MarkBridge → GitHub 更新** 明确同意并开启固定仓库稳定版检查；默认关闭。未启用主插件时，更新器保留独立设置入口。

开启后只检查 `wzf2000/MarkBridge` 的稳定最新版，接管主插件自身的更新候选，其他插件不受影响。下载必须同时验证版本、固定资产 URL、SHA-256、ZIP CRC、包内外清单和全部文件，随后交给 WordPress 原生升级器。检查不等于安装，GitHub 候选禁止自动升级；关闭后清理本适配器的缓存并恢复原生渠道，已打开的旧 GitHub 升级请求会明确拒绝。

网络请求限制 HTTPS 目标、重定向、时间与实际流式字节量，不发送站点地址、WordPress Cookie 或访问令牌。摘要提供完整性检查，不能防止受信仓库或发布账号本身被攻陷，也不是发布者签名。独立更新器的源码、模型、包及实际核心升级证据分别维护，不能把模拟 GitHub 响应称为真实远端验收。

正式开启任何新更新渠道前，先在测试站确认草稿、来源、配对、修订及回退方案；安装包升级不覆盖数据库配置或自动迁移文章。安装、检查、升级和发布限制见[安装与升级](INSTALL.md)、[验证范围](VALIDATION.md)与[发布流程](RELEASING.md)。
