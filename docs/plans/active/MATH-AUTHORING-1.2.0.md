## 问题与当前边界

- 可视化段落直接输入 `$a = b$` 是普通RichText文本，未创建公式对象。`src/kernel.js` 的 `textMD()` 对普通文字中的美元符转义，因此保存为 `\$a = b\$`；这是现有文字保真策略，不宜直接取消转义来解决输入问题。
- `src/inline-math-editor.js` 能渲染和编辑已有 `span.mbb-math[data-mbb-tex]`，但没有便捷的新建工具栏入口或成对美元符输入转换。Markdown导入则能创建行内公式。
- 当前WordPress核心同时注册名为 `core/math` 的RichText格式和区块；二者是不同注册表。行内格式保存 `<math data-latex>` 与MathML，区块属性为 `latex`/`mathML`，并带有布局、颜色等支持。不是MarkBridge现有 `mbb/math` 格式／区块，也不能只换渲染CSS就获得双格式兼容。
- MarkBridge行内保存TeX span，行间保存 `mbb/math` 的 `tex`；当前白名单与转换器未适配核心数学对象。行间编辑器已有源码及CHTML预览，但缺少 `$$` 回车变换。
- 上述问题为实施前的基线，用户截图为交互反馈；本轮隔离验收进度见上方实施进度，未将历史发布结果视为本版结果。

## 建议产品行为

1. 托管文档工具栏提供统一“数学”入口：无选区插入公式，选中文本可作为TeX初值；使用现有MathJax CHTML与小预览，支持确认、取消和键盘操作。
2. 在受支持的正文RichText中键入闭合 `$a = b$` 后转换为MarkBridge行内对象；一次撤销恢复原文字，不因再次观察同一文本而立刻重转。普通美元金额、转义美元、代码、未闭合表达式保持文字。不能在保存时重新猜测全篇美元符语义。
3. 空段落中仅键入 `$$` 并回车，变为行间公式区块，焦点进入TeX输入；一次撤销恢复段落。首版不把已有正文段落、代码块或多行粘贴中的 `$$` 误当快捷指令。
4. 行间公式在插入器显示明确名称“行间公式”，提供公式预览和源码编辑；沿用已有存储格式。非选中时优先显示渲染效果，选中后编辑，具体键盘焦点行为在实施前细化。
5. 在MarkBridge托管编辑会话统一新建入口，避免“数学”和“行内公式源码”重复。普通非托管文章保留WordPress原生行为；原生对象的解析注册不能粗暴注销，不能覆盖WordPress核心文件或依赖核心专用private API。
6. 既有原生数学对象提供显式“转换为MarkBridge公式”；只有可恢复且可验证的TeX才转换。缺少TeX、无法支持的公式、或无法保真的样式/属性需说明并保留原内容，不能静默丢弃。加载文章不自动写库，升级不批量迁移。

## 阶段及执行顺序

### P1：输入契约与核心兼容探查

固定当前核心行内和区块fixture，核对TeX来源、MathML、deprecated保存格式与样式属性。确认托管/普通/来源绑定文档的入口范围，确定键入识别规则、粘贴策略、撤销和中文输入法组合边界。检查核心功能可用性，缺失时提供MarkBridge入口而非报错。

### P2：行内公式新建与键入转换

先补稳定的新建/选区工具栏入口，再做 `$…$` 键入识别。通过RichText数据及撤销模型更新，避免仅改DOM导致保存丢失。覆盖段落、标题、引用及列表中的受支持文本；代码、链接地址、属性与编辑器外页面不扫描。初步仅处理本次用户输入附近的范围，不重解析整篇文章。

### P3：行间快捷输入与编辑体验

为 `mbb/math` 增加段落 `$$` + Enter 变换、插入器名称与焦点流，支持空公式创建后编辑、取消/撤销、不误吞下一段。核对发现当前核心 `enter` 变换没有取消触发回车的默认动作，且对所有区块属性匹配，无法满足段落专属和一次撤销约束。改用当前托管段落 RichText 上的局部键盘处理，严格限定光标、格式和允许列表；不安装全局回车监听。

### P4：原生数学入口协调与格式适配

在托管上下文控制新建入口，保留核心已有对象可读可编辑。实现核心行内/区块到MarkBridge格式的受控转换与明确反馈；尽量统一渲染体验，但不将全站核心数学渲染器替换作为前提。先完成转换模型再隐藏重复入口，保证始终有可用插入方式。嵌套内容、原生MathML的清理与不支持属性拒绝必须经过现有安全链。

### P5：保存回归、验收及发行准备

补转换fixture、真实Gutenberg键盘/鼠标测试与CI，验证原生保存、Markdown预览保存、精确修订恢复、冲突和权限。隔离通过后再准备生产合成草稿验收和1.2.0包；按届时明确授权部署/推送/发行，不沿用1.1.1单次发布授权。

## 完成标准

- 输入 `$a = b$`、工具栏新建、选区转公式三条路径均可渲染、编辑、保存、重开，Markdown为公式语法；文本美元仍被正确保真转义。
- `$$` + Enter只在规定段落条件触发；可继续输入公式和下段正文，撤销/重做、光标与中文输入法无丢字或重复转换。
- 相邻公式、中英文混排、上下标、分式、operatorname、无效TeX、粘贴与跨格式选区均有明确行为；空/无效输入不得吞文字或保存损坏对象。
- 核心行内/区块fixture转换后TeX与Markdown往返一致；无法保留的原生属性明确阻止或要求用户选择，不能静默删除。核心MathML不得绕过HTML过滤。
- 1.1.1既有公式、任务列表、脚注、代码和长文差异不回归；CHTML仅用于显示，不写入配对正文。无DOM重复挂载、公式裁切或明显长文输入卡顿。
- 普通非托管文章不被接管；文件来源文章仍走授权目标、双端指纹、差异预览和确认；文章ID、作者、发布规则、评论、私人笔记、绑定及修订保持。
- 真实编辑器桌面/手机测试覆盖点击、键入、撤销/重做、保存重开与失败保留；CI覆盖稳定可自动化的部分，并区分模拟测试和实际WP验收。
- 发布需干净构建、最终ZIP验收、匹配转换运行环境和协调回退方案，不自动修复历史转义正文或迁移原生数学文章。

## 已采用的范围决策与后续项

- 自动识别：托管文档默认开启，保留显式工具栏；转义/代码与撤销作为保留字面文本方式。仅自动识别本次闭合美元符前至多200字符的保守范围；金额、纯数字、跨格式与零间隔相邻公式保留文字。本版不增加全局关闭设置。
- 粘贴：本版不自动公式化粘贴内容；完整Markdown走已有导入，纯文本选区可显式转公式。
- 原生兼容：提供区分名称的工具栏入口并支持显式转换，不全站替换核心注册或自动迁移历史文章。原生对象必须先完成受控转换才可进入现有双格式保存；不直接接受任意MathML。
- 行内/行间相互转换：不是本轮必须项，可作为后续增强；自动保存、通用第三方区块适配和渲染器切换也不加入本版。

## 源码和接口依据

- `src/kernel.js`：公式Markdown解析、`textMD`转义、`mbb/math`格式/区块注册。
- `src/inline-math-editor.js`：已有公式显示与弹层编辑。
- 当前核心 `wp-includes/js/dist/format-library.js`、`wp-includes/blocks/math/block.json`、`wp-includes/js/dist/block-library.js`：核心数学格式、区块与序列化；实施时重新核对目标版本。
- [WordPress Block Transforms](https://developer.wordpress.org/block-editor/reference-guides/block-api/block-transforms/)：公开 `enter` 变换接口。

通用实现、测试与文档进入公开主仓库；任何站点路径、凭据、内容映射和部署证据只留私有工作区。此计划不修改1.1.1发布事实，也不代替实施与验收结果。

## 候选部署与回退边界

完成隔离验收后保留候选 ZIP、源码提交、独立文件清单及匹配转换运行环境。生产切换前重新核对现有安装文件和设置，备份当前插件与运行路径；切换插件和匹配环境后先用未发布的合成草稿检查公式输入、保存和重开。公开推送、PR 和 Release 另按明确授权执行，不把候选当作正式版。

本版继续使用已有 TeX span 与数学区块格式，不需要批量改写文章或迁移数据库。回退协调恢复旧插件及旧运行路径，保留此后文章、配对修订、来源文件和用户数据，不导入旧数据库覆盖后续编辑。真实来源文章仍按既有预览、权限和双端指纹规则写回。
