# 编辑可靠性与真实 WordPress 自动验收

状态：ACTIVE。目标版本：1.4.0。2026-10-12 启动，基线为已发行的 1.3.0。

## 范围与执行顺序

1. 在固定 WordPress 核心、合成数据库和最终安装包上执行真实保存链，生成核心脚本运行环境，补齐浏览器 CI 中此前明确跳过的核心编辑器测试。
2. 为 PHP／Node 转换错误提供可证明的原文行或区块位置与处理建议。不能确定位置时明确省略，不泄露正文、路径或认证材料。
3. 在托管区块编辑器中说明可转换范围，及时提示不支持的内容或属性；保留用户输入和服务端最终校验。
4. 按正文、评论及动态内容需要加载代码、复制、表情和脚注展示资源，保留管理员显示偏好。
5. 对最终包进行审查、自动验收与候选升级，完成正式发行及当前文档更新后归档本计划。

## 不变量

- PHP 新安装默认、管理员验证后可选择 Node，两个后端同步维护，不自动回退。
- 保持 schema 1、既有配对、修订、文章身份、权限、评论、私人笔记与受信来源校验。
- 不删除不能转换的区块，不批量重新生成正文，不迁移数据库，不自动保存或自动发布文章。
- 普通非托管文章保持原生编辑流程；评论、归档、查询循环和多文章展示继续工作。
- 公共源码与安装包不包含站点配置、内容、映射、凭据或部署记录。

## 完成标准

- PHP／Node 的代表性不支持语法、区块、属性及容量错误均有一致、安全的诊断；未知位置不误报。
- 编辑器提示能说明当前限制，用户内容不被提示功能改写，原生保存与既有冲突保护继续通过。
- 无相关内容时不加载重型展示依赖；存在相关正文、评论或后来插入的内容时正确加载，禁用偏好仍有效。
- 真实 WordPress 对最终 ZIP 执行 PHP／Node 保存、重开、权限、指纹冲突与配对修订检查；浏览器使用真实核心资源，不以替代 parse／serialize 充当核心验收。
- 格式、合成转换矩阵、包清单与固定源码发行检查通过；未测浏览器、核心版本和第三方组合明确保留边界。

## 后续候选

草稿恢复、Frontmatter、图片导入、日常导出、三方合并、更多区块、本地化及发行渠道扩展不在本轮。后续排期以当前需求和实际能力缺口为准，不因版本号自动启动。
