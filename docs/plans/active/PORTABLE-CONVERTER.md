# 免额外运行环境：PHP 转换架构改进

状态：**ACTIVE — 第一阶段可行性已验证，完整适配待启动**。本计划是独立架构版本，版本号待兼容性结论后确定；当前发行和生产仍为 1.2.0，不提前承诺上传即用。

## 目标与约束

普通用户仅上传 ZIP 并启用，即可导入、编辑和保存受支持的 Markdown/区块；基础使用不要求 Node、npm、Python、WP-CLI、子进程、Linux 沙箱或私有运行目录。开发工具可以在构建时使用，不能转嫁给安装者。受信服务器文件的绑定与写回仍需管理员显式配置。

保留文章身份、双格式正文、修订、权限、内容过滤、发布规则、冲突保护和来源契约。不信任浏览器传来的配对 HTML，不为兼容未知区块静默删属性。历史恢复与编辑后的规范化必须分开处理。转换失败不进入写入链。

## 阶段与准入

1. **PHP 可行性（本次启动）**：隔离实验目录，评估解析库；代表性 Markdown→区块→Markdown 与当前 Node 引擎差分；记录拒绝、差异、性能和依赖。允许结论为部分可行或不可替换，不把样例通过称为完整兼容。
2. 内容契约与完整适配：明确规范结构、属性策略、历史配对恢复、语法兼容及资源上限，覆盖现有支持矩阵。
3. 保存链集成：统一转换接口，覆盖原生 REST、Markdown、修订、来源写回及 CLI；现有权限、冲突、事务和回退保护不变。
4. 双引擎对照与安装：PHP 默认候选、Node 过渡对照；无 Node/禁用进程执行的干净 WordPress 安装验收。
5. 隔离升级和生产灰度：只在明确部署授权后进行，保全内容与配对历史，不能整库覆盖后续编辑。
6. 正式发行：完整验证后确定独立版本，更新安装与兼容说明；插件市场上架另行审查。

阶段 1 已完成受限子集验证（22 个源样例中 PHP 支持 15 个，15 个与当前 Node 区块逐字节一致；9 项拒绝与编辑断言通过）。结论与可复现命令见[实验说明](../../../experiments/php-converter/README.md)。其余阶段未启动；不自动接入生产、不切换保存后端、不发布新版本。

## 第一阶段验收问题

- PHP 可以产生编辑器接受的区块吗？不是只有 HTML 看上去相似。
- 区块反转是否真实解析内容，而不是返回缓存的原文？修改后能正确反映吗？
- 中文强调、代码中的特殊字符、引用公式、任务列表和命名脚注分别能保留哪些语义？
- 未知块、额外属性、危险 URL/HTML、复杂嵌套和超限输入是否拒绝？哪些尚未验证？
- 与当前引擎有何差异：字节、规范结构、拒绝策略或真实信息丢失？
- PHP 实验本身能否在禁用进程执行下运行？Node 只能作为外部测试对照，不能被 PHP 间接调用。
- 测量仅代表合成样例，不能外推成生产容量或完整安全结论。

`experiments/php-converter/`，不被生产插件加载，也不在发行代码白名单中。使用合成文档，不读取真实文章或来源映射。复现方式、依赖选择、已验证范围及缺口随实验结果更新；本计划在完整架构版本完成前保持 active。
