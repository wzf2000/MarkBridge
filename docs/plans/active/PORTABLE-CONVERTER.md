# 免额外运行环境：PHP 转换架构改进

状态：**ACTIVE — 第五阶段历史兼容修复与只读复核完成，生产灰度待批准**。本计划是独立架构版本，版本号待兼容性结论后确定；当前发行和生产仍为 1.2.0，不提前承诺上传即用。

## 目标与约束

普通用户仅上传 ZIP 并启用，即可导入、编辑和保存受支持的 Markdown/区块；基础使用不要求 Node、npm、Python、WP-CLI、子进程、Linux 沙箱或私有运行目录。开发工具可以在构建时使用，不能转嫁给安装者。受信服务器文件的绑定与写回仍需管理员显式配置。

保留文章身份、双格式正文、修订、权限、内容过滤、发布规则、冲突保护和来源契约。不信任浏览器传来的配对 HTML，不为兼容未知区块静默删属性。历史恢复与编辑后的规范化必须分开处理。转换失败不进入写入链。

2. **内容契约与完整适配（本阶段隔离验证完成）**：明确规范结构、属性策略、历史配对恢复、语法兼容及资源上限，覆盖现有支持矩阵。
3. **保存链集成（隔离验收完成）**：统一转换接口，覆盖原生 REST、Markdown、修订、来源写回及 CLI；现有权限、冲突、事务和回退保护不变。
4. **双引擎对照与安装（候选范围完成）**：PHP 默认候选、Node 过渡对照；无 Node/禁用进程执行的干净 WordPress 安装验收。
5. **隔离升级和生产灰度（限定调查与隔离验收完成，生产待批准）**：只在明确部署授权后进行，保全内容与配对历史，不能整库覆盖后续编辑。
6. 正式发行：完整验证后确定独立版本，更新安装与兼容说明；插件市场上架另行审查。

阶段 1 已完成受限子集可行性；2026-10-08 用户授权继续后，阶段 2 已完成现有主要内容类型适配、真实反转和严格历史配对恢复。89 个源样例的显式接受/拒绝预期全部满足，66 个共同支持样例区块逐字节一致并通过双向对照；7 份历史配对的 49 项检查、17 项测试方法（含 9 组资源输入）通过。PHP/样例指纹在整轮测试前后相同。可复现命令和限制见[实验说明](../../../experiments/php-converter/README.md)。

此结论限于隔离候选契约。危险 URL、图片替代文本丢失风险、重复 HTML 属性采用明确拒绝，共 4 个样例与 Node 接受策略不同；原文、规范原文及区块各 256 KiB，也不是生产容量承诺。阶段 3 通过显式启用、诊断显示限制与超限拒绝隔离这些差异；默认切换前仍须评估容量和这些兼容差异，不把本阶段样例覆盖称为所有历史文章、第三方区块或全版本完全兼容。第三阶段以显式 PHP 后端接入现有保存入口，保持原默认选择且失败不自动回退；第四阶段已完成下述新安装默认策略和隔离安装验收；第五阶段已进入只读兼容调查和隔离升级，生产灰度及发行尚未启动；不自动接入生产、不切换保存后端、不发布新版本。

## 第三阶段集成结果

默认仍为 Node；仅服务器常量 `MARKBRIDGE_CONVERTER_BACKEND='php'` 显式启用候选。诊断检查 PHP 8.2+、DOM/mbstring、WordPress 7.1 模板、依赖摘要与同名类冲突；不满足时拒绝，不自动改用 Node。原有保存入口统一调用 Worker，保留权限、指纹、事务及来源路径校验。未修改的合法历史配对保留原快照，修改后的区块必须真实逆转。

禁用外部进程的真实隔离 WordPress 验证通过：原生 REST 保存、发布规则、修订恢复及失败回滚；Markdown 预览、作者/编辑/管理员权限、源文件与数据库双端冲突、安全写回、协调失败回退和 CLI 同步。测试前后既有文章正文及身份指纹一致。Worker 的 6 项接口测试覆盖文档身份、历史版本、伪造配对、批处理和错误边界。

本阶段没有完成无 Node 干净安装、真实编辑器浏览器复核、PHP/WordPress 版本矩阵、生产容量调查或升级灰度。阶段 4 应先处理依赖命名空间隔离、安装条件与明确拒绝策略，再考虑默认启用。正式版及生产配置均未变。

## 第四阶段安装结果

- 新安装没有旧运行目录配置时默认 PHP；已有非空常量或数据库运行目录配置保留 Node，显式后端常量优先。选择依据配置，不因目录失效或转换失败自动换引擎。
- 固定 PHP-Scoper 0.18.19 与构建工具锁，把依赖移入私有命名空间。独立类加载表不共享 Composer 运行状态；外部同名库可共存，冒占私有前缀、依赖缺失及清单失配明确拒绝。原始 src/vendor、构建工具不进入 ZIP；旧隔离产物不能冒充新源码。
- WordPress 7.1 干净站通过后台上传 ZIP 并启用；只有 MarkBridge，无后端常量或运行目录。Web 进程 PATH 不含可执行程序，外部进程函数全部禁用。安装后 2,253 个文件与外部清单一致。测试机仍有供开发对照/浏览器驱动使用的 Node，不宣称从整台机器卸载 Node。
- 真实浏览器通过上传 Markdown、预览、新建草稿、行内公式键入、原生保存与重开；异步 MathJax 完成后检查桌面及手机尺寸。修复脚本强制 HTTPS 导致 HTTP 新站导入入口不可用；资源跟随 WordPress 配置协议。
- PHP 8.2.32 与 8.5.8 各通过 17 项转换测试、10 项后端/接口测试。重新执行 89 个源样例与历史配对对照通过。已安装包在 PHP 8.2 通过原生 REST、修订、权限/冲突、源文件写回/CLI及协调失败回退；PHP 8.5 原生 REST 保存与修订回归也通过。Node 旧配置诊断与源写回测试通过。

仍限定 WordPress 7.1 模板、DOM/mbstring、256 KiB 原文/规范原文/区块与现有明确拒绝策略；未覆盖所有 PHP 中间版本、其他 WordPress 版本或任意共享主机。PHP 8.5 的 WP-CLI 自身依赖出现弃用提示，测试仍通过；缺失 DOM 扩展未直接实测。下一阶段处理真实容量/历史内容兼容调查、隔离升级与协调回退，再准备经明确批准的生产灰度。完整架构版本和后台配置体验尚未完成，当前公开发行仍为 1.2.0。

## 历史内容的迁移处理顺序

本轮先明确处置，未执行生产内容迁移。历史表示差异不等于正文损坏；修订中的配对哈希只能证明字段曾一起记录，不能代替转换器对来源与完整快照的验证。

1. **优先保留原配对，补有限旧表示兼容（已实现并复核）**：已在只读内存中验证一种旧表示模式：从合法原文完整生成后，仅把 HTML 文本 token 的 `&gt;` 还原为 `>`，标签、属性及所有区块注释保持原样，可以逐字节重现对应旧快照。已实现为内部固定 `html-text-gt-v1` 历史 renderer，保留原有限额、HTML/属性/公式检查，再以完整字节相等准入。不得对客户端快照做宽泛归一化，也不得以 DOM 等价或修订哈希直接放行；不使用受全局过滤器影响的 `wp_kses_post()` 作为兼容规则。字面实体、代码、公式、属性与注释保护、篡改拒绝、收缩前生成物限额及只读复核均通过。此路径不重写正文、来源、绑定或旧修订。
2. **先排除转换器重复处理，再要求改稿（已实现并复核）**：已有合法数学标记内部的 `$…$` 会再次被识别并包装，形成嵌套数学 span。已补已识别公式的幂等处理，验证原 HTML 实体层及 TeX、文本、允许属性完全对应；任意子元素、属性或不匹配内容仍拒绝。不可先删文章格式，或为了通过而允许任意公式子树。合成和只读复核通过；对应现有配对已可原样保留，不需为了重复包装问题改稿。
3. **HTML 结构拒绝逐项审阅（待准备候选）**：行内标签边界不匹配及块 HTML 非法名称／定界符单列处理。先确定唯一源与作者意图：确为标签则补正结构，确为文本则转义。不得直接保存 DOM 自动修补结果、全局 strip 标签、删除源绑定或把修订元数据改成“可信”。当前结构诊断不足以确定具体稿件补丁，不声称已完成源文件所有权、映射或修订历史核验。
4. **仅必要时做显式内容迁移**：必须先选定权威来源，合并现有区块编辑；经源与 WordPress 双端新鲜指纹、差异／预览确认、限定备份后，使用既有配对保存链创建新合法配对及修订。保留 ID、作者、可见性、链接、评论、私人记录与绑定；旧修订不篡改。不同内容家族使用自己的唯一源和同步规则，不能从数据库旧 Markdown 无条件批量重生。
5. **区分升级回退与内容恢复**：优先仅回退插件／后端并保留后续内容。原本已被拒绝的旧配对，不能承诺经普通修订接口恢复；若确需恢复原字节，必须另备经审阅的按条目条件恢复路径，发现迁移后新编辑即停止，不整库覆盖。事务内失败回滚不等同于提交后内容恢复演练。

2026-10-08 上述两项修复已纳入隔离候选并完成只读复核。PHP 8.2／8.5 各 25 项转换测试、7 项 Worker 测试及 1 项资源测试（9 组输入）通过；后端选择 4 项、源码／语法／格式检查通过。新增 4 份普通合成源与真实 Node 完整输出逐字节相等；独立审查的 4 项目标测试及 11 组定向输入通过。既有 144 源／61 配对矩阵通过，不把少量新 Node 对照冒称全矩阵重新对照。

历史 profile 只作用于受限生成物，实体收缩前后都检查容量，不改变新导入或实际编辑的规范输出。公式既验证原始 HTML 片段，再验证完整结果，防止先转义真实子元素再误放行。双字段公式编辑可实际反转，单字段篡改仍拒绝。私有只读复核确认表示差异与重复包装项均已通过，原配对字段精确保留；剩余 HTML 结构问题仍须按第 3 项审阅。

已确认一项原有 PHP／Node 差异：独立 `core/html` 中已编码的 `<3` 公式可在反转重导入时因裸 HTML 边界而被 PHP 拒绝，旧 PHP 候选同样拒绝而 Node 接受；普通 Markdown 比较公式及普通段落中的合法实体公式不受此项影响。此边界已锁定拒绝测试并在实验说明记录，不宣称所有 raw HTML 公式兼容。

下一步准备明确范围的生产灰度及剩余 HTML 稿件审阅；不依据只读调查自动启用 PHP、重写文章或修订。私有条目、统计、诊断、所有权和部署材料继续只留私有工作区。

## 第一阶段验收问题

- PHP 可以产生编辑器接受的区块吗？不是只有 HTML 看上去相似。
- 区块反转是否真实解析内容，而不是返回缓存的原文？修改后能正确反映吗？
- 中文强调、代码中的特殊字符、引用公式、任务列表和命名脚注分别能保留哪些语义？
- 未知块、额外属性、危险 URL/HTML、复杂嵌套和超限输入是否拒绝？哪些尚未验证？
- 与当前引擎有何差异：字节、规范结构、拒绝策略或真实信息丢失？
- PHP 实验本身能否在禁用进程执行下运行？Node 只能作为外部测试对照，不能被 PHP 间接调用。
- 测量仅代表合成样例，不能外推成生产容量或完整安全结论。
