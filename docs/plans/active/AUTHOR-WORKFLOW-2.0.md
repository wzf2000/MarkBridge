## 阶段 2 已确定的边界

Front Matter 采用文件开头的显式版本标记 `---`／`markbridge: 1`，值使用单行 JSON，头部最多 16 KiB。闭合字段为标题、摘要、固定链接名称、保存状态、已有分类／标签的 slug 和特色图片 ID；不引入作者、任意元数据或自动建分类。没有版本标记的历史 YAML 继续作为正文处理，未经明确编辑不迁移旧配对。

原始头部作为唯一首块保存，不输出前台 HTML。头部是作者提案，与 WordPress 当前元数据分别保留：预览逐项显示当前值与提案，默认不选择任何字段；选择变化后重新预览。正常编辑文章设置不隐式重写头部，需要反映到 Markdown 时显式生成候选，再经过正常预览与确认。

服务端对完整候选和选择签发校验凭据，保存时在文档锁内重新检查文章版本、权限、分类／标签存在性、固定链接冲突、发布与特色图片规则；仅应用明确选择的字段。正文、来源写回和元数据使用同一保存链，实际值不符或失败时协调回滚。恢复历史正文不会自动应用历史头部提案，也不会借此恢复当前分类或发布状态。本阶段已经完成隔离验收，实际环境与局限见验证说明；不代表八项或正式版已完成。

## 图片与导出的设计约束

图片包只接受用户本地上传的 Markdown 与 PNG／JPEG／GIF／WebP，不能输入服务器目录或让服务端抓取任意 URL；SVG 等主动内容不在首期范围。预览暂存不创建媒体库附件，确认后才上传并改写正文链接，配对保存失败仅清理本次新建资源。已绑定服务器源文件不推断 ZIP 的图片路径映射，需要明确的受信适配才能写入相关资源。

沿用 WordPress 普通媒体行为：草稿和私密文章中的静态媒体 URL 仍可能公开访问。导入前须清楚提示并明确确认这一点，不把附件权限或文章可见性冒充文件下载保护。导出 ZIP 只包含明确关联且可验证的本地附件；外部 URL 原样保留并在资源清单说明，不按 URL 猜测路径或遍历媒体目录。上述为后续阶段约束，尚未实现或验收。

## 区块适配的范围预案

第 6 阶段优先核验原生 `core/details` 与 `core/buttons`／`core/button`。保留它们的原生区块身份，使用明确版本化的 Markdown 表达，不把按钮丢失为普通段落，也不把有分组语义的 `details name` 等同于已有折叠块标识。属性和保存 HTML 都须闭合；样式、互斥分组或动作按钮等未能表示的内容明确拒绝。

原生保存形状以受支持的 WordPress 版本实际 `wp.blocks.parse/serialize` 为准，分别核验落库快照和前台渲染，不能用渲染后 HTML 冒充保存源码。扩展适配只能由受信代码登记；正文不携带转换脚本。具体准入字段在进入该阶段时确定，此预案不是已完成清单。

## 不变量

- 主插件保留一份通用源码和同一发行包；站点配置、部署、源映射、凭据、真实内容不进入公共源码。
- 保留 schema 1、每种正文 256 KiB、PHP 默认／管理员选择 Node、不自动后端回退；新格式和准入同步维护两个后端。
- 保留文章 ID、作者、状态权限、固定链接、分类、评论、修订、私人笔记、来源 realpath/hash 及双端版本冲突规则。新文章仍经确认保存草稿，发布仍遵循特色图片与现有权限。
- 恢复、导入与合并只准备候选，仍须差异／预览和明确确认。已有文件来源只能写回绑定真实目标，不输入任意服务器路径，不新增第二份可写正文源。
- 本地存储默认关闭，不存 nonce、cookie、私有环境／源路径；共享浏览器风险明确说明。作者配置和读者运行状态继续分离，恢复不假称已保存。
- 图片与导出只使用当前用户有权读取的本地资源，拒绝路径穿越、链接逃逸、危险格式、解压炸弹和任意网络抓取；不删除既有附件。
- 扩展只由受信代码登记，文章不能携带可执行转换器。发行适配独立于主插件，WordPress.org 包不通过外部服务分发可执行更新。

## 验收与交付

各阶段覆盖成功路径、权限、直接失败、并发或容量边界；编辑器覆盖桌面／手机、刷新、重开和未保存输入保留。真实合成 WordPress 使用独立库，区分 mock 与实际保存；涉及配对、元数据、图片和来源的更改覆盖修订恢复与失败回退。最终包按外部可信清单验安装，PHP 8.2／8.5 和匹配 Node 运行环境直接验证，其他版本与浏览器按实际边界记录，不用旧 CI 冒称新结果。
