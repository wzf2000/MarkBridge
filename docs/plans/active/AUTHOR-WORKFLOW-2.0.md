## 阶段 2 已确定的边界

Front Matter 采用文件开头的显式版本标记 `---`／`markbridge: 1`，值使用单行 JSON，头部最多 16 KiB。闭合字段为标题、摘要、固定链接名称、保存状态、已有分类／标签的 slug 和特色图片 ID；不引入作者、任意元数据或自动建分类。没有版本标记的历史 YAML 继续作为正文处理，未经明确编辑不迁移旧配对。

原始头部作为唯一首块保存，不输出前台 HTML。头部是作者提案，与 WordPress 当前元数据分别保留：预览逐项显示当前值与提案，默认不选择任何字段；选择变化后重新预览。正常编辑文章设置不隐式重写头部，需要反映到 Markdown 时显式生成候选，再经过正常预览与确认。

服务端对完整候选和选择签发校验凭据，保存时在文档锁内重新检查文章版本、权限、分类／标签存在性、固定链接冲突、发布与特色图片规则；仅应用明确选择的字段。正文、来源写回和元数据使用同一保存链，实际值不符或失败时协调回滚。恢复历史正文不会自动应用历史头部提案，也不会借此恢复当前分类或发布状态。本阶段已经完成隔离验收，实际环境与局限见验证说明；不代表八项或正式版已完成。

## 图片与导出的设计约束

图片包只接受用户本地上传的 Markdown 与 PNG／JPEG／GIF／WebP，不能输入服务器目录或让服务端抓取任意 URL；SVG 等主动内容不在首期范围。预览暂存不创建媒体库附件，确认后才上传并改写正文链接，配对保存失败仅清理本次新建资源。已绑定服务器源文件不推断 ZIP 的图片路径映射，需要明确的受信适配才能写入相关资源。

沿用 WordPress 普通媒体行为：草稿和私密文章中的静态媒体 URL 仍可能公开访问。导入前须清楚提示并明确确认这一点，不把附件权限或文章可见性冒充文件下载保护。导出 ZIP 只包含明确关联且可验证的本地附件；外部 URL 原样保留并在资源清单说明，不按 URL 猜测路径或遍历媒体目录。图片导入与 ZIP 导出分别完成阶段隔离验收；它们是独立入口，不把其中一项的结果当作另一项验收。

## 阶段 4 的导出合同

仅导出当前用户有权编辑的已保存托管文章，验证原文／区块精确配对并要求当前版本令牌。预览返回闭合的资源清单，确认下载前再次检查权限、版本、资源身份与摘要；不以未保存编辑器输入冒充当前文章。绑定文件来源的文章仅导出 WordPress 已保存配对，不读取文件或输出绑定路径。Markdown 单文件保留原始字节与 Front Matter；ZIP 为便携图片引用生成明确标记的规范副本，不覆盖文章或源文件，代码、链接与原始头部保留。

ZIP 资源限正文实际引用、具有 WordPress 当前文章直属附件关系、经媒体 API 返回值精确核对的本地图片。首期不从当前无法往返的区块附件 ID 推断归属；有界枚举文章直属的受支持图片，再对实际引用匹配，不要求图片必须由本插件导入。最多枚举该文章有界关联集合，不全库查询、不按 URL 猜路径、不抓取远端；未关联、外部或无法验证的 URL 保留并说明。文件须为 uploads 根内的普通文件，所有路径组件不得为符号链接；验证实际类型、尺寸、SHA-256、单个／总量与归档上限。仅支持安全图片，不打包任意附件类型或运行环境。

清单使用固定、版本化、闭合的 JSON，只含逻辑资源名、类型、大小、摘要及明确的有限文章元数据，不含作者、密码、任意 post meta、评论、私人笔记、来源／部署路径或凭据。若 ZIP 携带此清单，导入器只接受并验证这一种已知侧文件，不因此开放任意 JSON 文件；不能隐式应用清单中的发布状态、封面 ID或文章身份。已有 Front Matter 提案仍遵循明确选择和权限。导出不自动发布，也不生成第二份在线可写正文。

图片、展开后、归档入口及 ZIP 大小须符合可重新导入的边界；超限明确拒绝，不静默删图或截断。临时包位于私有目录，设置严格权限和 no-store 下载，正常、取消与失败路径均有界清理。本阶段已完成固定源码、PHP 8.2／8.5／Node 实际合同及桌面／手机 HTTP 验收；最终固定安装包完整回归仍待主计划收口。

## 阶段 5 的合并合同

三方基线 A 必须来自冲突发生前的已核验完整配对，并由服务端签名绑定当前用户、站点、文章／类型、文档身份、预期版本、源／区块摘要和短时有效期；文件托管再绑定服务端来源身份与当时文件摘要。签名不是免鉴权的访问令牌，每次仍检查权限与当前绑定。浏览器不持久保存此凭据；旧本地恢复记录或缺少可信 A 时保留现有手动比较／候选下载，不能把最新版本倒充基线。

文件实际源与已保存配对原文可能不同。此时首期拒绝自动三方合并，提示先通过正常预览／来源协调保存建立一致基线；不假设两者天然一致。新操作也必须检测来源换绑，而非只比较恰好相同的文件字节；来源身份只输出不可反推路径的签名投影，不导出真实路径或改动既有路径绑定。

界面明确区分“打开时版本”“我的候选”“服务器最新版”。独立变化和相同变化可以形成候选；重叠、同位置插入和无法可靠区分的重复结构要求逐项明确选择。保留 CRLF、孤 CR、空白及末尾换行差异，不以简单 split／join 静默改写。Front Matter、教学头部、围栏等闭合结构有界按整体处理，不拼出半个结构。三份正文分别服从 256 KiB、32,768 行，局部差异至多 12,000 单元，并有整次工作上限；超预算明确转手动处理／下载，不近似猜测合并。

合并只产生未保存候选，保留原候选下载。采用之前重新核验服务器版本、来源和权限；采用后再次走正常差异／预览与明确保存，仍以该服务器快照检查最终冲突。不增加第二条文章或源文件写入链，不借自动合并更改作者、状态或其他元数据。本阶段已实现并完成隔离验收；实际范围与失败记录见验证说明，完整候选仍待后续阶段收口。

实现采用独立的只读打开基线、读取最新版与确认采用接口，签名只在会话内保留。打开基线从服务器配对生成，不从编辑框或未保存区块倒推；没有可签的旧基线时明确退回手动比较。通用版本指纹增加按站点域分离的绑定 HMAC 投影，检测同内容换绑，不输出可字典猜测的裸路径摘要。最新版凭据绑定打开基线、当前候选摘要、最新正文／元数据和来源；采用接口再次校验并转换合并候选，但不保存文章。

合并计算属于有界的纯文本候选处理，不作为可信转换器；最终 PHP／Node 都仍走各自完整转换和配对保存。标题、状态与特色图片也比较三份值：我的值相对打开基线未变化时保留服务器值；两边重叠变化时须明确选择，不通过采用新指纹静默恢复旧元数据。成功保存后建立新的签名打开基线，旧会话、输入变化或凭据过期不复用旧结果。

## 区块适配的范围预案

第 6 阶段优先核验原生 `core/details` 与 `core/buttons`／`core/button`。保留它们的原生区块身份，使用明确版本化的 Markdown 表达，不把按钮丢失为普通段落，也不把有分组语义的 `details name` 等同于已有折叠块标识。属性和保存 HTML 都须闭合；样式、互斥分组或动作按钮等未能表示的内容明确拒绝。

原生保存形状以受支持的 WordPress 版本实际 `wp.blocks.parse/serialize` 为准，分别核验落库快照和前台渲染，不能用渲染后 HTML 冒充保存源码。扩展适配只能由受信代码登记；正文不携带转换脚本。首期接入原生 details 与链接型 buttons／button，保留中性默认属性；非空互斥分组、样式或动作按钮等无法表达的结构拒绝。扩展首期仅支持受信登记的静态叶子：闭合字段与有限安全节点模板，无正文脚本或任意 HTML。登记、缺包／版本拒绝、双引擎一致性和真实核心保存形状仍须完成验收；此处不是已完成清单。

## 不变量

- 主插件保留一份通用源码和同一发行包；站点配置、部署、源映射、凭据、真实内容不进入公共源码。
- 保留 schema 1、每种正文 256 KiB、PHP 默认／管理员选择 Node、不自动后端回退；新格式和准入同步维护两个后端。
- 保留文章 ID、作者、状态权限、固定链接、分类、评论、修订、私人笔记、来源 realpath/hash 及双端版本冲突规则。新文章仍经确认保存草稿，发布仍遵循特色图片与现有权限。
- 恢复、导入与合并只准备候选，仍须差异／预览和明确确认。已有文件来源只能写回绑定真实目标，不输入任意服务器路径，不新增第二份可写正文源。
- 本地存储默认关闭，不存 nonce、cookie、私有环境／源路径；共享浏览器风险明确说明。作者配置和读者运行状态继续分离，恢复不假称已保存。
- 图片与导出只使用当前用户有权读取的本地资源，拒绝路径穿越、链接逃逸、危险格式、解压炸弹和任意网络抓取；不删除既有附件。
- 扩展只由受信代码登记，文章不能携带可执行转换器。发行适配独立于主插件，WordPress.org 包不通过外部服务分发可执行更新。

## 验收与交付

当前权威知识写入架构、使用与验证文档；完成后归档本计划，不新建重复的完成总结。源稿／生产仅用于说明既有保护规则，不进行访问或写入。
