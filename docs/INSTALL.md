# 安装与升级

本文适用于 MarkBridge **1.2.0**。安装插件请下载现成的 Release ZIP，通过 WordPress 后台上传；日常写作的作者不需要自行构建插件。

**管理员还必须配置私有 Node.js 转换运行环境与 Linux 沙箱。** 上传 ZIP 并启用只完成插件安装，未配置运行环境时不能转换或保存双格式正文。当前未上架 WordPress.org 插件目录，不能从后台插件市场搜索安装。

## 安装前确认

| 要确认的条件                                                       | 谁来准备     |
| ------------------------------------------------------------------ | ------------ |
| WordPress 7.1，PHP 8.2+，PHP 启用 DOM、JSON 与 `proc_open`         | 站点管理员   |
| Linux 服务器，以及 Node.js 24 LTS（24.15.0+）、npm、Python、WP-CLI | 服务器管理员 |
| bubblewrap、timeout、所需命名空间与 PHP-FPM 访问权限               | 服务器管理员 |
| 可以安装插件的 WordPress 账号                                      | 站点管理员   |

当前最小验收基于 WordPress 7.1；未声明更早版本兼容。共享主机、Windows 和禁用进程创建的 PHP 环境没有经过验证。无法管理服务器时，先让站点管理员确认环境；完整要求与操作见[服务器配置](RUNTIME.md)。

## 1. 下载插件安装包

打开 [GitHub Releases](https://github.com/wzf2000/MarkBridge/releases)，选择要安装的正式版本，下载该版本的插件附件 **`markbridge-1.2.0.zip`**。

请选择插件安装包附件；GitHub 自动生成的 **Source code (zip)** 和 **Source code (tar.gz)** 是源码归档，供开发或管理员准备环境使用，不是后台上传的插件安装包。安装其他版本时使用对应版本附件与文档。

## 2. 在 WordPress 后台上传

1. 以管理员账号进入 **插件 → 安装插件 → 上传插件**。
2. 选择下载的插件 ZIP，点击 **现在安装**。
3. 安装成功后点击 **启用插件**。

如果已有旧版，先阅读本页的升级说明并准备备份，再使用 WordPress 的替换上传流程。不要把插件解压成第二份同时启用。

## 3. 请管理员配置转换运行环境

管理员按[服务器配置](RUNTIME.md)从同版本源码，在目标服务器的公共 Web 目录之外准备一个新的私有运行目录，并配置 Linux 沙箱与权限。

随后进入 **设置 → MarkBridge**，提交已经准备好的运行目录。候选目录通过兼容检查与沙箱转换后才保存；失败保留旧设置。如果管理员在 `wp-config.php` 中定义了 `MARKBRIDGE_RUNTIME`，则常量优先，后台不能覆盖。

后台设置页不会安装 Node 或系统软件，也不接受上传可执行运行环境。缺少运行环境时仍可进入设置与诊断，但配对转换和写入会被拒绝。沙箱失败不会改用无隔离执行。

## 4. 用一篇草稿确认可以使用

按照[快速开始](GETTING-STARTED.md)上传一份简单 Markdown，检查预览并保存为草稿。再重新打开文章，修改一个区块并保存，确认 Markdown 原文同步更新。

管理员还应检查历史恢复、含公式和代码的实际前台页，以及普通作者的权限。运行测试、配套保护文件和详细验收见[服务器配置](RUNTIME.md#4-最小验收)。预览成功不表示所有主题和插件组合都已验证。

## 升级前后怎么做

1. 备份数据库、旧插件、运行配置、上传资源，以及文件来源文章的源文件和同步映射；备份放在 Web 根之外。
2. 管理员核对新版本的运行环境要求。WordPress 升级或转换内核改变时，在**新目录**重新准备匹配环境，保留旧目录供回退，不覆盖使用中的目录。
3. 上传同版本插件 ZIP，协调切换运行配置，刷新升级前已打开的编辑器。
4. 重做草稿导入、区块保存、修订恢复和前台检查，确认后再继续日常编辑。

启用或升级不会自动批量迁移、改写或发布既有文章。旧版不能编辑新增的任务列表、脚注等格式，降级前须保全新增内容并协调恢复匹配的插件和运行环境。**不要直接用整库备份覆盖升级后新增的文章、评论或私人笔记。** 具体版本要求、显式迁移工具、文件来源契约和协调回退见[服务器配置](RUNTIME.md#升级与历史迁移)。
