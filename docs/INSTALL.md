# 安装与升级

本文适用于 MarkBridge **1.3.0-rc.1** 预发布候选。普通作者只需使用后台编辑器，不需要构建插件；管理员下载 Release 中的插件 ZIP 后上传并启用。本候选尚未正式发行，既有正式版本请阅读对应标签的文档。

## 安装前确认

| 条件      | 要求                                                      |
| --------- | --------------------------------------------------------- |
| WordPress | 7.1.x；其他核心版本在当前 PHP 候选中明确拒绝              |
| PHP       | 8.2+，启用 DOM、mbstring 和 JSON                          |
| 账号      | 可以安装、启用插件的管理员                                |
| 内容范围  | 受支持的 Markdown／区块；源、规范源及区块分别最多 256 KiB |

基础 PHP 转换不要求 Node、npm、Python、Composer、Linux 沙箱或 `proc_open`；依赖已随插件 ZIP 提供。不同 PHP 中间版本、共享主机、Windows、全部主题与第三方插件组合尚未完整验证，具体已验范围见[验证文档](VALIDATION.md)。当前未上架 WordPress.org 插件目录。

## 1. 下载插件安装包

打开 [GitHub Releases](https://github.com/wzf2000/MarkBridge/releases)，下载所选版本的插件附件 **`markbridge-<版本>.zip`**，候选附件标记为 Pre-release。

GitHub 自动生成的 **Source code (zip)**／**Source code (tar.gz)** 是开发源码，缺少构建资源，不是后台上传的安装包。不要以源码归档代替插件 ZIP。

## 2. 上传并启用

1. 进入 **插件 → 安装插件 → 上传插件**。
2. 选择插件 ZIP，点击 **现在安装**。
3. 安装成功后点击 **启用插件**。
4. 进入 **设置 → MarkBridge**，确认当前后端为 `php`，诊断通过。

全新安装没有旧运行目录设置时，自动使用包内 PHP 转换器，无需填写服务器目录。如果提示缺扩展或不支持的核心版本，请联系管理员处理；转换失败不会自动启用 Node，也不会改写原内容。图片资源和服务器源文件写回属于可选配置，见[服务器配置](RUNTIME.md)。

## 3. 用一篇草稿确认可以使用

按[快速开始](GETTING-STARTED.md)上传一个简单 `.md` 文件，检查差异和预览，再保存为草稿。重新打开，修改一个区块并保存，确认 Markdown 原文同步更新。

再检查一份含公式／代码／任务列表／脚注的草稿及修订恢复；有普通作者账号时确认其权限。预览成功不代表任意 HTML 或第三方区块都能转换。来源绑定文章仍需管理员配置受信目标，并显示差异后明确确认。

## 从旧版本升级

1. 在 Web 根之外备份旧插件、配置和受影响数据；文件来源保留真实路径、绑定和映射。
2. 上传新版本 ZIP，避免同时启用新旧副本，刷新旧编辑器窗口。
3. **已有非空 Node 运行配置升级后继续使用 Node。** 仅安装候选不会自动切换，保留原运行目录。
4. 管理员按[后端选择](RUNTIME.md#后端选择与诊断)显式选择 PHP，先检查诊断并用草稿验证保存、重开、修订和来源流程。
5. 有限灰度通过后再扩大使用。内容不兼容时先审阅原配对和最小差异，不批量重生，也不删除绑定以通过保存。

启用或升级不自动重写既有文章或旧修订。降级优先恢复相互匹配的插件／后端并保留后续内容；不能直接恢复整库覆盖新文章、评论或私人记录。原本无效的历史配对不保证能由普通修订接口恢复，必要迁移须另备条件恢复路径。Node 模式仍需要匹配核心和内核的私有环境，配置见[服务器配置](RUNTIME.md)。
