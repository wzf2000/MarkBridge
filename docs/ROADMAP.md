# 正式版路线与后续交接

记录日期：2026-09-17。当前候选版本：`0.7.0-rc.2`。

本文记录后续工作计划，不代表功能已实现或测试已通过。本轮只整理文档；后续执行者应先核验仓库、已发布版本与验收记录，再处理仍未完成的事项，避免重复工作。

## 起点与目标

先阅读 [README](../README.md)、[安装指南](INSTALL.md)、[架构说明](ARCHITECTURE.md)、[验收记录](VALIDATION.md)、[发布流程](RELEASING.md) 与 [贡献规范](../CONTRIBUTING.md)。验收事实以实际执行记录为准，不能把其他版本的结果等同于当前候选的全部验收。

核心编辑、双格式保存与恢复、冲突保护、公式、评论 Markdown、权限和回收站流程已有验收证据。回收站修复已纳入 rc.2，源码入口遗漏也已修复。

- **0.7.0**：在明确且有限的环境支持范围内完成正式发布，重点补齐验收，不预设需要增加核心编辑功能。
- **1.0.0**：在上述基础上改善安装诊断、升级与发布可靠性，以及普通作者的导入体验。

两阶段可以分别交接。1.0.0 的体验开发不作为 0.7.0 去掉 RC 的前置条件。

## 0.7.0：剩余验收与发布准备

以下任务记录时均为待完成。只有发现实际缺陷时才增加对应修复；无需因文档或打包调整反复运行整个复杂页面矩阵。

### R07-01 · 旧版升级与回退演练

使用完整隔离测试站与合成测试数据演练旧版本到当前候选的升级。现有证据只覆盖一篇旧文的存储兼容和停用保护，不能替代完整副本演练。

完成标准：

- 记录升级前后的版本、插件与主题组合及运行环境配置。
- 核对文章 ID、两种正文、修订、权限和来源绑定保持一致；抽验代表性的公式、代码及文件来源文档。
- 验证新运行环境的准备与切换，以及数据库、插件文件和运行环境的协调回退。
- 回退后重新检查可读性、保存与双格式一致性；不把备份文件存在或主插件停用当作恢复演练成功。
- 清理隔离数据与短期凭据，仅保留脱敏结果。真实文章、会话与数据库不得进入公开仓库。

### R07-02 · 补齐两条实际浏览器路径

- 匿名访客通过真实评论表单提交 Markdown，检查写入、审核状态及最终展示；保留正常 WordPress 评论权限和内容过滤。
- 通过区块界面实际创建含行内公式的段落，检查整段预览、配对保存、重开和前台排版，同时确认普通文字与代码未受影响。

完成标准：两条路径都有实际操作结果和清理记录。现有 WordPress 评论过滤链测试、Markdown 导入与公式展示测试可以复用，但不能替代缺失的点击路径。

### R07-03 · 最终发布包与支持声明

从明确的 Git 提交干净构建最终 ZIP，核对版本、依赖锁、必需源码、生成资源、许可与 SHA-256。按安装文档准备运行环境，在隔离站完成安装、导入保存、重开及回收站恢复的短验收。

完成标准：

- R07-01、R07-02 已完成，或发现的问题已修复并有针对性复验。
- README、安装文档与插件元数据准确描述实际支持范围；未验证的 WordPress、PHP、主题或主机环境不作兼容承诺。
- 最终源码提交、版本标签、安装包与校验值一一对应；不覆盖已有同版本的不同内容安装包。
- 更新 CHANGELOG、VALIDATION 与发布文案后，按届时授权执行 GitHub Release；生产升级独立处理。

广泛的版本与主题矩阵尚未完成。如果继续保持当前有限支持声明，它不是无限扩张的发布前置任务；扩大支持范围时再增加相应测试。

## 1.0.0：建议开发范围

以下均为待开发建议，开始实现前先核验是否已有等效能力。建议先完成高优先级任务，再实施中优先级任务；不以全面重构替代具体用户问题。

### R10-01 · 高优先级：后台运行环境诊断

当前缺少运行环境时主要显示配置提示。补充管理员可读的诊断页或诊断命令，检查配置路径、Node、bubblewrap、超时工具、文件权限、核心脚本快照和最小转换是否可用。

完成标准：正常与失败状态均有清晰原因和下一步操作；至少验证缺失运行环境、权限不足与转换失败。详细系统信息仅对有权限的管理员可见，不泄露凭据或通过诊断提供任意命令执行。复用现有隔离转换，不增加无沙箱后备执行。

### R10-02 · 高优先级：自动化发布检查

建立从干净检出开始的自动化检查，覆盖锁定依赖安装、格式、源码、构建、转换及安装包完整性。特别检查插件入口和构建必需文件均已提交，避免工作副本有文件而 Git 归档缺失。

完成标准：检查能在无生产配置、无生产数据的环境中复现；遗漏入口、版本不一致或必要资源缺失时明确失败；产物关联源码提交并输出校验值。自动检查不自动扩大为生产部署或公开发布。

### R10-03 · 中优先级：安装与升级辅助工具

改进现有运行环境准备工具，提供版本匹配检查、清晰的权限说明与可审阅的切换步骤，减少手工排错。优先支持现有 Linux 部署方式，不预设本阶段必须支持所有共享主机或跨平台。

完成标准：新目录构建和检查完成前不替换当前可用环境；失败保留旧环境；提供明确的切换、回退和清理说明，并在隔离站验证一次成功与一次失败路径。

### R10-04 · 中优先级：新建文章的 Markdown 导入入口

在新建文章的编辑流程中提供易发现的“导入 Markdown”入口，复用现有预览与配对保存流程。当前工具页入口继续可用，原生区块文章继续正常编辑。

完成标准：普通作者可从新建文章发现入口，导入后预览并保存草稿；取消不会写入内容或产生多余文章；已有未保存内容受到保护；权限检查、冲突保护和双格式保存不被绕过。

## 后续可选，不阻塞本轮正式版

- 脚注、正文任务列表和更多第三方区块。
- 后台编辑后写回外部 Markdown 文件。
- 更广泛的主机、WordPress、PHP 和主题兼容。
- 全面的面向对象重构。

这些事项需单独确定语义、支持边界与验收标准；不得为了去掉 RC 顺带扩展实现。

## 给后续执行者的交付约定

开始时选定任务编号并检查最新进展。保持 `mbb/*` 区块名、存储键、文章身份与权限契约；遇到需要改变公共契约的方案先说明兼容与迁移方式。

每项任务完成后记录最终提交、实际运行的检查、结果和未运行项，更新本文状态与 VALIDATION。验证按改动影响范围选择，复用已有证据；涉及真实编辑行为的验收不能只用离线检查代替。

本文只记录计划，不单独授权生产切换、批量迁移、删除真实内容、创建长期会话或自动发布。生产操作继续遵循目标站点规则与用户届时授权。受限环境中的敏感验收材料留在私有位置，公开文档只写脱敏结论。
