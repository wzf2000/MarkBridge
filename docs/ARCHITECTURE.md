# 工作原理

## 一篇文档，两种表示

`post_content` 保存 WordPress 区块序列化；`post_content_filtered` 保存 Markdown 原文。`_mbb_document_id` 是稳定身份，不能用标题或内容哈希代替。配对修订同时记录两种表示，恢复时检查权限、当前版本、内容策略与修订完整性。

浏览器负责编辑和预览，服务器重新转换并校验后才保存。浏览器提交的 HTML 不是可信转换结果。原生区块文章保持原生保存；托管 Markdown 文档必须经过配对保存流程。

## 转换进程

PHP 用共享非阻塞锁限制并发，通过 25 秒限时的 bubblewrap 子进程启动 Node。运行环境只读挂载到固定沙箱路径，网络命名空间隔离；worker 用 jsdom 与目标站点核心区块脚本进行转换，不加载外部页面。

运行环境由安装者从自己站点的核心脚本重建，不分发后台页面快照。插件 ZIP 不包含 Node、数据库、站点配置或运行环境。

## 公式

MathJax 在本地隔离 iframe 中转换，通过校验来源和请求标识的消息通信返回排版结果。正文保留 TeX 源码；公式预览不作为正文写回。选择含行内公式的段落时预览完整段落。

当前使用 MathJax 4.1.3 的 SVG 输出与 `mathjax-newcm` 字体，关闭引擎菜单和探索器。父页面插入的是序列化的 SVG 结果，不是带有 MathJax 菜单事件的原始引擎节点；只改变 `enableMenu` 不能提供页面上的渲染器切换。块公式在内容区居中，超宽公式由容器横向滚动；行内公式保持行内布局。

## 文件来源与兼容

`_mbb_source_managed=file` 的文档以外部 Markdown 文件为源；后台只读，CLI 同步检查实时文件内容与来源路径哈希。旧 wp-editormd 编码的还原函数保留许可来源；不依赖旧插件类或文件。

代码按转换、存储、修订、公式与展示拆分，尚未完成全面面向对象重构。格式化改善了阅读，但不改变现有公共数据契约。

## 统一发行与配置

主插件目录来自同一发行 ZIP；数据库选项 `mbb_runtime_path` 仅在服务器未定义 `MARKBRIDGE_RUNTIME` 时生效。管理员设置与诊断即使在首次未配置时仍可访问；候选路径通过隔离转换后才切换。内核、worker、核心快照、启动快照和发行依赖契约校验失败时，配对写入在数据库事务前被拒绝。

可选图片表情放在上传目录 `markbridge/emoji/`，数据库保存 `markbridge_emoji_packs` 与 `markbridge_emoji_active`。前端按选择解释短代码，不重写正文或评论。ZIP 仅接受清单声明的受限图片数据，默认不下载外部资源。

发行清单记录源码提交与文件哈希；安装核验使用外部可信清单。数据库设置、独立资源和私有转换环境不属于主插件文件差异。WordPress 原有 hooks 继续用于独立集成，无需维护实例专用主插件分支。
