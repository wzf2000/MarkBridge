# 工作原理

## 一篇文档，两种表示

`post_content` 保存 WordPress 区块序列化；`post_content_filtered` 保存 Markdown 原文。`_mbb_document_id` 是稳定身份，不能用标题或内容哈希代替。配对修订同时记录两种表示，恢复时检查权限、当前版本、内容策略与修订完整性。

浏览器负责编辑和预览，服务器重新转换并校验后才保存。浏览器提交的 HTML 不是可信转换结果。原生区块文章保持原生保存；托管 Markdown 文档必须经过配对保存流程。

## 转换进程

PHP 用共享非阻塞锁限制并发；新安装直接执行随包提供的 PHP Worker，不创建子进程。已配置 Node 的兼容模式通过 25 秒限时的 bubblewrap 子进程启动 Node，运行环境只读挂载、网络命名空间隔离；worker 用 jsdom 与目标站点核心区块脚本转换，不加载外部页面。

仅 Node 兼容运行环境由管理员从站点核心脚本重建，不分发后台页面快照。插件 ZIP 不包含 Node、数据库、站点配置或运行环境。

## 原生区块保存

非文件来源的托管文章使用核心文章 REST 更新入口。前端随请求携带打开时的版本指纹，仅成功响应推进基线；服务端取得文档锁，在一个事务内让 WordPress 原生控制器执行权限、元数据、分类与正文更新。`rest_pre_insert` 复用候选转换、内容过滤与发布校验，同时设置 Markdown 字段；所有步骤成功且双格式核验通过才提交，并维护配对修订及来源历史。失败回滚并清理相关缓存。

版本指纹覆盖双格式正文和原生可编辑字段、REST 分类及已注册的 REST 元数据，不包含编辑锁等运行字段。文件来源和自动保存／修订子路由继续受保护。第三方钩子产生的邮件或外部 HTTP 等事务外副作用无法由数据库回滚，不能把此保证理解为任意插件的分布式事务。

## 公式

MathJax 在本地隔离 iframe 中转换，通过校验来源和请求标识的消息通信返回排版结果。正文保留 TeX 源码；公式预览不作为正文写回。区块编辑器中的行内公式以 Shadow DOM 显示 CHTML，轻 DOM 保留原始 TeX；点击公式打开源码及小型预览浮层，应用时仅通过 RichText 更新原公式对象。打开时的 TeX 与当前对象不一致则拒绝覆盖。编辑器 iframe 各自挂载字体样式，展示节点不进入序列化正文。

无脚本 srcdoc 预览保持空 sandbox；其不透明来源不能直接使用站点字体，因此只将受信 MathJax 字体目录下、经过大小与 WOFF2 文件头检查的字体嵌入预览 CSS。加载失败会阻止确认保存并允许重试，不放宽 iframe 权限。

1.2.0 的公式输入层只对托管编辑器启用：RichText 工具栏显式新建保留纯文本边界；闭合美元符识别限定本次 `beforeinput` 与对应 RichText 更新，通过核心导出的历史动作建立可撤销边界，能力缺失时保留文字。普通美元符转义及服务端严格往返规则不变。行间快捷输入使用当前段落的局部键盘处理，限定完整 `$$`、末尾折叠光标、无附加格式及允许插入该区块；取消本次回车默认动作后创建公式，避免向新源码框多写换行。不增加全局回车处理。

原生数学通过独立显式转换入口接入，保留 `core/math` 两种注册。非空 MathML 先校验受支持结构和 TeX 注释，再调用核心公开 `@wordpress/latex-to-mathml` 模块重建并比较结构，最后验证 MathJax 可排版。模块不可用、结构不一致或额外属性会拒绝转换；异步结束时再次比较对象与选区，避免覆盖新编辑。转换输出仍为既有 TeX span 或 `mbb/math`，不放宽通用 HTML 策略。托管区块插入器过滤核心数学入口，同时尊重既有允许列表；普通文章不变。

当前使用 MathJax 4.1.3 的 CHTML 输出与 `mathjax-newcm` 字体，关闭引擎菜单和探索器。父页面插入的是序列化的 CHTML 结果及配套样式，不是带有 MathJax 菜单事件的原始引擎节点；只改变 `enableMenu` 不能提供页面上的渲染器切换。块公式在内容区居中，超宽公式由容器横向滚动；行内公式保持行内布局。

### 编辑画布公式样式

MathJax CHTML 会按已使用的结构和字形动态补充样式。渲染服务将更新同步到注册的同源编辑画布文档与行内公式 Shadow DOM；新建画布立即取得当前样式，失效画布在后续同步时剔除。区块预览独立注册所在文档，不依赖正文里先有行内公式。样式仅用于显示，不写入配对正文。

### 前台阅读工具

正文公式可点击，或获得焦点后按 Enter / 空格打开原生阅读弹窗。弹窗复用已生成的 CHTML，默认 150%，以 25% 为步长在 100%–300% 间调整；重置和重新打开恢复默认大小。长公式在弹窗内横向滚动，不改变正文大小或保存内容。

“复制 TeX”使用浏览器剪贴板接口，失败时选中只读源码供手动复制。Esc 或关闭按钮退出并恢复公式入口焦点；迟到的复制结果不能干扰下一次阅读。排版失败仍显示原始 TeX，源码不作为 HTML 执行，也不写入浏览器持久存储。

链接内公式和可编辑区域不添加阅读入口，保留原交互。静态、无脚本的编辑预览继续显示 CHTML，不注入不可操作的阅读按钮。此功能不提供渲染器切换，也不等同于完整数学探索器或语义无障碍支持。

## 文件来源与兼容

`_mbb_source_managed=file` 的文档以外部 Markdown 文件为源；配置受信目标且权限与双端指纹通过后可网页写回，其余保持只读。CLI 同步独立检查实时文件内容与来源路径哈希。旧 wp-editormd 编码的还原函数保留许可来源；不依赖旧插件类或文件。

代码按转换、存储、修订、公式与展示拆分，尚未完成全面面向对象重构。格式化改善了阅读，但不改变现有公共数据契约。

## 统一发行与配置

主插件目录来自同一发行 ZIP；数据库选项 `mbb_runtime_path` 仅在服务器未定义 `MARKBRIDGE_RUNTIME` 时生效。管理员设置与诊断即使在首次未配置时仍可访问；Node 候选路径通过隔离转换后才保存。Node 内核、worker、核心快照、启动快照和发行依赖契约校验失败时，配对写入在数据库事务前被拒绝。

可选图片表情放在上传目录 `markbridge/emoji/`，数据库保存 `markbridge_emoji_packs` 与 `markbridge_emoji_active`。前端按选择解释短代码，不重写正文或评论。ZIP 仅接受清单声明的受限图片数据，默认不下载外部资源。

发行清单记录源码提交与文件哈希；安装核验使用外部可信清单。数据库设置、独立资源和私有转换环境不属于主插件文件差异。WordPress 原有 hooks 继续用于独立集成，无需维护实例专用主插件分支。

## 差异与冲突交互

编辑桥使用按行比较和唯一行锚点划分修改片段，小范围使用有界 LCS，大范围重复内容按替换展示。每片段首批最多 200 行，首批最多 20 个片段，后续由用户展开，避免长文一次生成大量 DOM。

预览和保存发生版本冲突时，保留候选并锁定编辑字段，提供 Markdown 下载和服务器最新版比较。来源文章须同时读取匹配的文章指纹与源文件指纹；读取失败或期间再次变化时禁止采用新基线。用户明确选择保留候选并继续后，必须重新预览才能保存。不自动合并、不绕过服务端校验、不将候选存入浏览器持久存储。关闭弹窗后丢弃迟到异步结果。

## 正文任务列表

简单普通列表继续使用 `core/list`。含任务（包括嵌套任务）的列表使用 `mbb/list`，普通项为 `mbb/list-item`，任务项为 `mbb/task-item`；后者保存 `content` 与布尔 `checked`，后续块保留为 innerBlocks。持久化 HTML 使用安全文字标记而不保存 input；区块渲染阶段仅为任务项生成禁用复选框。正文不再泛化替换普通文字标记，评论仍沿用原规则。

服务端 allowlist 接受新块但不放宽 KSES。旧复杂任务文字快照通过历史解析器的完整序列化精确比对恢复；私有 worker 的 `paired_restore` 同时接收历史 Markdown 与区块，REST 不增加对应公开模式。来源身份、指纹、权限、修订验证保持原路径。编辑后的内容仍须严格往返；不静默忽略属性或转换不支持的块。

## 脚注

命名引用由 `span.mbb-footnote-ref[data-mbb-footnote]` 保留名称及原始标记，编辑器注册独立 RichText 格式。唯一的顶层 `mbb/footnotes` 位于文末，包含 `mbb/footnote{label}` 与正文 InnerBlocks；定义顺序保留，显示编号不进入存储。脚注解析使用锁定的 markdown-it-footnote，在其搬移定义前检查重复、孤儿、非法名称及嵌套引用，避免默认解析行为静默丢弃内容。

服务端通过正常 KSES 和区块 allowlist 处理这些安全标签，不存储 input 或可执行内容。`mbb_render_footnotes` 在前台与 REST 预览共同生成按首次引用排序的编号、文档作用域唯一锚点及每次引用的返回链接；跳过代码/链接中的伪标记，重复渲染保持幂等。前台不引入写入接口。

编辑桥 srcdoc 预览显式内联受信脚注 CSS，将片段链接指向 `about:srcdoc`，避免 iframe 点击脚注时错误加载父页面。脚注引用工具栏按完整标记边界改名，不把相邻引用一并替换。

旧解析器只用于完整源/区块快照精确匹配的兼容恢复；新导入仍执行严格脚注引用完整性检查。未改变文章身份、来源绑定、权限、冲突检测及配对保存/修订流程。

## PHP 转换候选（未发行）

架构候选的新安装默认 PHP，已有非空 Node 目录配置保持 Node，依据配置选择而非转换失败后回退。可用服务器常量 `MARKBRIDGE_CONVERTER_BACKEND='php'` 显式选择 PHP；`mbb_convert()` 统一分派，原有权限、来源绑定、指纹、修订与事务层不变。后端错误不自动重试另一引擎。

PHP 的单一实现位于 `plugin/includes/php-converter/`，Worker 适配 Markdown 导入、区块反转、精确配对恢复及批处理协议。未编辑的已验证历史配对保留原文和快照，编辑后的区块需真实反转再验证。依赖在构建阶段按 Composer 锁文件安装并通过固定 PHP-Scoper 隔离命名空间，随包携带；不与其他插件共享 Composer 加载器。摘要或私有命名空间冲突检查失败即拒绝转换。当前准入限定 PHP 8.2+、DOM/mbstring 和 WordPress 7.1.x 模板，仍有 256 KiB 文档边界及明确语法拒绝差异。

本地保存链、依赖隔离与干净候选安装已经通过；这不代表 PHP 已作为正式发行默认项。已验版本、容量限制与下一阶段升级灰度见[架构计划](plans/active/PORTABLE-CONVERTER.md)。
