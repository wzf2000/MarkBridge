# 工作原理

## 一篇文档，两种表示

`post_content` 保存 WordPress 区块序列化；`post_content_filtered` 保存 Markdown 原文。`_mbb_document_id` 是稳定身份，不能用标题或内容哈希代替。配对修订同时记录两种表示，恢复时检查权限、当前版本、内容策略与修订完整性。

浏览器负责编辑和预览，服务器重新转换并校验后才保存。浏览器提交的 HTML 不是可信转换结果。原生区块文章保持原生保存；托管 Markdown 文档必须经过配对保存流程。

托管编辑器展示共享区块能力列表，用于提示支持的区块类型；该 JSON 只声明区块名称和少量需校验属性的类型，不表示区块可带任意属性。浏览器可对当前区块执行往返检查，但不改写编辑输入，也不替代保存时服务器重新转换、属性校验及配对验证。未知或无法可靠映射的位置不报告为具体行号。

转换错误保留既有 Worker 错误码，缺失或无效时使用 `conversion`，并在错误数据中追加安全的 `conversion_code`、可选位置、结构化位置与处理提示；无法确定的位置留空。诊断不包含正文片段或文件路径。

原文框为未编辑的上传、服务器读取、恢复和资源替换保留内存中的原字符串，显示投影不作为新源码；Front Matter 重建也保留原 body。实际输入后采用浏览器文本框内容并提示换行处理。异步文件读取检查会话和输入版本；恢复的两次鉴权等待分别检查同一会话、输入版本与目标，等待自身关闭事件完成后才打开下一会话。关闭／重开或继续输入后，迟到结果不得注入新的候选。

## 转换进程

PHP 用共享非阻塞锁限制并发；新安装直接执行随包提供的 PHP Worker，不创建子进程。已配置 Node 的兼容模式通过 25 秒限时的 bubblewrap 子进程启动 Node，运行环境只读挂载、网络命名空间隔离；worker 用 jsdom 与目标站点核心区块脚本转换，不加载外部页面。

仅 Node 兼容运行环境由管理员从站点核心脚本重建，不分发后台页面快照。插件 ZIP 不包含 Node、数据库、站点配置或运行环境。

## 原生区块保存

非文件来源的托管文章使用核心文章 REST 更新入口。前端随请求携带打开时的版本指纹，仅成功响应推进基线；服务端取得文档锁，在一个事务内让 WordPress 原生控制器执行权限、元数据、分类与正文更新。`rest_pre_insert` 复用候选转换、内容过滤与发布校验，同时设置 Markdown 字段；所有步骤成功且双格式核验通过才提交，并维护配对修订及来源历史。失败回滚并清理相关缓存。

版本指纹覆盖双格式正文和原生可编辑字段、REST 分类及已注册的 REST 元数据，不包含编辑锁等运行字段。文件来源和自动保存／修订子路由继续受保护。第三方钩子产生的邮件或外部 HTTP 等事务外副作用无法由数据库回滚，不能把此保证理解为任意插件的分布式事务。

### 版本化头部提案（2.0 开发中）

Front Matter 只识别文件开头的 `markbridge: 1` 头部，使用单行 JSON 值与闭合七字段；PHP／Node 共享大小、字符、结构和拒绝边界。完整原始头部放在唯一首块 `mbb/frontmatter` 的 `version`／`raw` 属性中，保存包装固定且前台渲染为空。未经编辑的精确历史配对仍走既有兼容恢复，不将宽松历史解析用作新候选写入入口。

文章当前元数据与头部提案分离。客户端仅提交选择字段；服务端从已验证配对解析提案，解析已有 term slug、检查权限和固定链接冲突，签发绑定站点、用户、文章、完整候选、双端基线和解析结果的短期 HMAC 凭据。保存在现有文档锁内重新转换、鉴权、解析并核验凭据，只应用明确选择的字段。数据库事务与已有来源写回共同失败恢复；文件恢复和数据库回滚分别尝试，失败明确报告。附件、任意元数据和作者不属于头部字段。

原生 REST 保存保留头部提案，不接受借此选择元数据。历史恢复也不自动应用历史提案。编辑桥重新打开或生成头部时，只在真实读取的指纹仍等于已持有基线时更新当前正文与元数据视图；服务器已变时保留原基线和候选，由原有冲突流程处理，不能用刷新界面绕过并发校验。

### 本地资源导入（2.0 开发中）

`resource-import.php` 只管理本地 ZIP 的私有暂存、校验、预览计划和本批媒体恢复记录，不独立保存正文。暂存按运行 UID、站点和登录用户隔离，目录 0700／文件 0600，拒绝 Web 根内路径、链接与错误所有者；临时会话绑定文章、文档身份及打开时版本，15 分钟到期。PHP zip、intl、POSIX 和媒体上传权限仅是此可选入口的条件，不成为普通 PHP 转换的新增依赖。

ZIP 按真实流读取和校验大小／CRC，最多 8 MiB 压缩、32 MiB 展开、100 项、一个 Markdown、32 张受支持位图；拒绝危险条目和路径逃逸。图片只有通过实际类型、尺寸、摘要和绑定检查才进入计划。普通链接、代码和既有外部 URL 不由服务端下载或导入；文件来源文章不推断资源映射。PHP／Node 的 `resource_images` 变换只作用于已校验的配对快照，最多 256 种图片地址映射、32 个不同目标，保留头部并重新验证闭合配对。

预览只显示有界图片和目标替换后的候选，不创建媒体。父页重新鉴权读取图片并核验字节、MIME 和 SHA-256；空 sandbox 的不透明来源不能读取父页 Blob URL，因此使用总量最多 8 MiB／1600 万像素的图片 data URI，重复引用也计入。仅容量不足显示占位；网络、权限、类型或摘要失败使确认失效。上传／确认期间修改、关闭和切换会话均检查候选版本及会话标识，等待本地恢复授权后也再次检查，旧请求不能改变新文档的目标。

确认前明确告知 WordPress 静态媒体可能公开。服务端凭据绑定完整正文、表单元数据、选择、资源计划与基线；保存时在原文档锁和事务中创建附件、变换最终媒体 URL、核对元数据和双格式，再关联附件与提交。专属公有目录标识从私有会话单向派生；私有凭据不进入最终正文或本地恢复。原图、缩放图和尺寸副本的专属目录在生成前记入签名恢复记录，失败仅清理本批文件，不能依赖已回滚的附件元数据判断归属。

数据库提交返回失败不等于实际回滚。配对与原生保存都观察直接数据库基线；提交结果不确定时保留新源文件、媒体和私有记录，返回明确的 `commit_uncertain`，不能把一次 `ROLLBACK` 的成功响应当作未提交证明。源文件回退还须重新读取当前绑定与内容摘要，只恢复本次写入仍未被第三方改动的目标。恢复或取消中断批次时重新核验文章配对及附件关联；不能证明安全时继续保留并要求核对，不删除既有媒体。

### 已保存文章导出（2.0 开发中）

`export.php` 提供只读上下文、准备、确认下载和取消接口。入口重新鉴权，只接受已保存的托管配对及完整版本指纹；`paired_restore` 校验原文与区块，不读取文件来源目标。确认下载再次核对权限、文章身份、指纹和图片摘要。浏览器只提交闭合的身份、格式与确认凭据，不提交正文作为服务器版本。

Markdown 保留原字节；短期记录只含有界的身份、摘要和期限，不持久化正文副本。ZIP 只引用正文实际使用、经当前文章直属附件关系与媒体 API 精确 URL 核对的本地位图，验证 uploads 根、所有路径组件、所有者、实际 MIME、尺寸和摘要；不猜测路径或抓取远端内容。PHP／Node 的 `portable_images` 使用真实图片目标范围生成便携副本，保留代码、普通链接和原始头部，并重新验证语义。

导出槽按站点和用户隔离，四个有界槽、15 分钟期限。ZIP 在创建目录或建包前原子登记 `preparing`，完成后再次验证文章与资源，比较交换为 `ready`；中断或取消不能复活旧任务。确认下载只有原子领取成功才输出字节，失败清理仅限本次可验证的候选。私有目录 0700、文件 0600，拒绝符号链接、错误所有者与 Web 根。导出的版本化清单只含便携文档、资源摘要和闭合元数据；资源导入验证结构与摘要，不自动应用这些元数据。

### 会话内三方合并（2.0 开发中）

`merge.php` 的打开、最新版和采用接口只读取、鉴权与转换，不保存文章。打开基线 A 来自服务端核验的完整配对；HMAC 绑定用户、站点、文章类型／身份、来源投影、完整版本、正文摘要、标题／状态／封面和短期有效期。最新版 C 还绑定 A 及当前候选 B 的摘要。每次再次鉴权、检查来源真实目标及读取前后版本；来源文件与配对不同、过期或换绑时拒绝自动合并。签名只保留在浏览器当前会话。

`src/merge.js` 按原始换行做有界候选比较：三份正文各最多 256 KiB／32,768 行，局部差异至多 12,000 单元，整次工作和冲突数也有上限。Markdown 真实解析范围把代码围栏、HTML、头部和教学容器作为完整结构；重复或重叠无法可靠识别时要求选择，不近似猜测。标题／状态／封面各自比较作者意图，B 未修改时保留 C，其他元数据保持 C 与既有明确提案流程。

采用接口重新核验 C 并通过所选 PHP／Node 后端转换；返回未保存候选和 C 的保存基线，仍须正常预览、明确保存。来源重读改变最终展示版本时重新签与该版本完全匹配的打开基线；无法匹配降为手动。所有迟到错误检查输入版本，成功保存响应与其后的本地恢复清理分别处理，避免覆盖新输入或把已提交结果说成回滚。

### 原生区块与受信静态适配（2.0 开发中）

`core/details`、`core/buttons` 和 `core/button` 保留原生身份，通过版本化闭合 Markdown 载体双向转换。准入同时验证原始注释属性和实际核心保存结构，避免核心解析的默认值或丢弃属性掩盖内容损失；不支持的样式、互斥分组或动作按钮明确拒绝。详情内部使用已有正文 AST，并复用内部锚点展开和打印恢复，不增加可写阅读状态。

静态适配由受信 PHP 通过 `mbb_register_block_adapter()` 登记有限字段和安全节点模板。文章只保存名称、版本和参数；所有字段必填，模板没有回调、任意 HTML、URL 或脚本。服务器拥有规范描述快照，统一传入浏览器、PHP／Node Worker 及 batch；请求和正文不能覆盖它。规范登记摘要进入原有绑定版本投影，预览确认及转换／提交前再次核验，登记变化使用原有冲突和协调回退规则。缺包保留静态正文和配置，并拒绝不能核验的转换与恢复。接口和预算见[原生区块与静态适配接口](BLOCK-ADAPTERS.md)；本阶段已完成限定隔离验收，完整候选和后续阶段仍在推进。

## 公式

MathJax 在本地隔离 iframe 中转换，通过校验来源和请求标识的消息通信返回排版结果。正文保留 TeX 源码；公式预览不作为正文写回。区块编辑器中的行内公式以 Shadow DOM 显示 CHTML，轻 DOM 保留原始 TeX；点击公式打开源码及小型预览浮层，应用时仅通过 RichText 更新原公式对象。打开时的 TeX 与当前对象不一致则拒绝覆盖。编辑器 iframe 各自挂载字体样式，展示节点不进入序列化正文。

无脚本 srcdoc 预览保持空 sandbox；其不透明来源不能直接使用站点字体，因此只将受信 MathJax 字体目录下、经过大小与 WOFF2 文件头检查的字体嵌入预览 CSS。加载失败会阻止确认保存并允许重试，不放宽 iframe 权限。

1.2.0 的公式输入层只对托管编辑器启用：RichText 工具栏显式新建保留纯文本边界；闭合美元符识别限定本次 `beforeinput` 与对应 RichText 更新，通过核心导出的历史动作建立可撤销边界，能力缺失时保留文字。普通美元符转义及服务端严格往返规则不变。行间快捷输入使用当前段落的局部键盘处理，限定完整 `$$`、末尾折叠光标、无附加格式及允许插入该区块；取消本次回车默认动作后创建公式，避免向新源码框多写换行。不增加全局回车处理。

原生数学通过独立显式转换入口接入，保留 `core/math` 两种注册。非空 MathML 先校验受支持结构和 TeX 注释，再调用核心公开 `@wordpress/latex-to-mathml` 模块重建并比较结构，最后验证 MathJax 可排版。模块不可用、结构不一致或额外属性会拒绝转换；异步结束时再次比较对象与选区，避免覆盖新编辑。转换输出仍为既有 TeX span 或 `mbb/math`，不放宽通用 HTML 策略。托管区块插入器过滤核心数学入口，同时尊重既有允许列表；普通文章不变。

当前使用 MathJax 4.1.3 的 CHTML 输出与 `mathjax-newcm` 字体，关闭引擎菜单和探索器。父页面插入的是序列化的 CHTML 结果及配套样式，不是带有 MathJax 菜单事件的原始引擎节点；只改变 `enableMenu` 不能提供页面上的渲染器切换。块公式在内容区居中，超宽公式由容器横向滚动；行内公式保持行内布局。

### 编辑画布公式样式

MathJax CHTML 会按已使用的结构和字形动态补充样式。渲染服务将更新同步到注册的同源编辑画布文档与行内公式 Shadow DOM；新建画布立即取得当前样式，失效画布在后续同步时剔除。区块预览独立注册所在文档，不依赖正文里先有行内公式。样式仅用于显示，不写入配对正文。

### 前台阅读工具

正文公式可点击，或获得焦点后按 Enter / 空格打开原生阅读弹窗。弹窗复用已生成的 CHTML，默认 150%，以 25% 为步长在 100%–300% 间调整；重置和重新打开恢复默认大小。长公式在弹窗内横向滚动，不改变正文大小或保存内容。

“复制 TeX”使用浏览器剪贴板接口，失败时选中只读源码供手动复制。Esc 或关闭按钮退出并恢复公式入口焦点；迟到的复制结果不能干扰下一次阅读。排版失败仍显示原始 TeX，源码不作为 HTML 执行，也不写入浏览器持久存储。

链接内公式和可编辑区域不添加阅读入口，保留原交互。静态、无脚本的编辑预览继续显示 CHTML，不注入不可操作的阅读按钮。此功能不提供渲染器切换，也不等同于完整数学探索器或语义无障碍支持。

## 文件来源与兼容

`_mbb_source_managed=file` 的文档以外部 Markdown 文件为源；配置受信目标且权限与双端指纹通过后可网页写回，其余保持只读。CLI 同步独立检查实时文件内容与来源路径哈希。旧 wp-editormd 编码的还原函数保留许可来源；不依赖旧插件类或文件。

代码按转换、存储、修订、公式与展示拆分，尚未完成全面面向对象重构。格式化改善了阅读，但不改变现有公共数据契约。

## 统一发行与配置

主插件目录来自同一发行 ZIP；`mbb_converter_settings` 单一对象原子保存引擎与 Node 路径，旧 `mbb_runtime_path` 保留，仅在新选项缺失且无路径常量时沿用。管理员设置与诊断即使首次未配置或当前使用 PHP 时仍可选择 PHP／Node；目标引擎通过服务端完整诊断及实际转换后才保存。Node 内核、worker、核心快照、启动快照和发行依赖契约校验失败时，配对写入在数据库事务前被拒绝。

可选图片表情放在上传目录 `markbridge/emoji/`，数据库保存 `markbridge_emoji_packs` 与 `markbridge_emoji_active`。前端按选择解释短代码，不重写正文或评论。ZIP 仅接受清单声明的受限图片数据，默认不下载外部资源。

发行清单记录源码提交与文件哈希；安装核验使用外部可信清单。数据库设置、独立资源和私有转换环境不属于主插件文件差异。WordPress 原有 hooks 继续用于独立集成，无需维护实例专用主插件分支。

## 阅读展示资源

代码高亮与复制、表情和脚注样式按实际内容按需加载。检测覆盖正文区块与内容过滤结果，也会检查当前查询中的文章；浏览器侧的小型观察器处理首次输出之后动态加入的正文或评论内容。数学展示、代码、脚本和可编辑区域不会被表情扫描器当作普通文本处理。代码行号与复制按钮继续遵守管理员的显示偏好；资源按需加载不改变正文、评论或转换结果。

## 教学内容（未发行候选）

`src/teaching.js` 与 PHP `Teaching` 共同实现闭合的 `:::mbb:v1` 语法，`mbb/collapse`、`mbb/steps`、`mbb/step` 和 `mbb/code-compare` 均持久化 `version:1` 与唯一稳定 ID。解析内部标记使用本次转换的随机 nonce，原文不能伪造内部容器；nonce 不进入持久正文。双方校验 Unicode 标题、属性类型、围栏、锚点冲突、结构深度／节点和三通道容量，原配对 schema 不变。

区块保存的是静态安全外壳与作者 InnerBlocks；前台脚本仅渐进增强显示。折叠与阶段切换通过隐藏属性保留作者 DOM，目录和评论可同步揭示目标。history 仅增加命名空间内的阅读快照，保留其他组件状态；对应 URL 的返回快照优先于自动锚点展开。打印与无脚本显示全文，临时控件标记 `data-mbb-generated`，作者正文与原代码不作生成内容排除。

代码对照保存左右原始字符串；围栏反转选择足够长的分隔符，不修改原空白。小型代码使用有界 LCS，长代码退化为明确标注的同行位置比较。每侧首批 400 行标注、最多 2,000 行；整篇初始最多 4,000 行、手动标注最多 8,000 行，剩余源码保留文本和复制。普通 Prism 与对照展示隔离，避免高亮替换差异节点；对照不是保存差异，也不执行代码。

### 多语言代码页签（2.0 候选）

`mbb/code-tabs` 保存闭合的有序代码版本数组、组与版本稳定 ID 和明确默认项；不接受任意 InnerBlocks，也不执行代码。v1 容器的 JSON 只保存 ID、标题与末尾 LF 标记，语言由顺序对应的围栏给出；经真实 AST 确认后从原始源范围读取代码，保留 CRLF、孤 CR、缩进与缺少尾 LF 的代码。HTML 与普通围栏中的字面教学标记不会成为容器；内部原码标记仍绑定本次随机 nonce，不信任正文伪造的标记。

PHP／Node 共同校验 JSON 数组与对象身份、全局锚点、默认引用、1–8 版、64／128 KiB 代码预算和既有三通道上限。保存外壳包含所有版本的静态 `pre/code`；实际 KSES 后的原码恢复仅来自已经严格验证的配对，不扩大其他 HTML 准入。真实区块的编辑、复制组和排序沿现有配对、修订、权限、来源与冲突链。

前台配置从已验证属性投影原码，复制与原字节下载不从被 HTML 或 Prism 规范化的 DOM 反推。此组禁用 Prism 的通用复制控件，保留本地高亮及行号；未知语言使用纯文本展示，不根据作者语言值加载任意资源。页签通过保留节点、命名空间 history 和既有目标揭示配合折叠／阶段；错误配置保持静态，全文／打印／无脚本显示全部版本。

### 受信组件与运行边界

`mbb/component` 以同一 v1 教学格式保存类型、组件版本、稳定实例标识、纯 JSON 参数和静态 InnerBlocks。转换器不依赖具体提供者；保存层核验完整基线配对后，允许保留已有配置，新建或修改配置必须通过兼容提供者的封闭 schema。真实 WordPress KSES 后恢复的参数来自已验证配对，不凭正则外壳或客户端基线授权。空对象、数组、字面文本与有限双精度数在 PHP／Node 之间保持语义。

独立插件登记固定本地资源、SHA-256、协议、最低主插件版本和实际预算。服务端注册表是资源权威，不从文章属性接受 URL；编辑器注册表在已登记脚本之前输出，内核明确依赖该脚本，避免 WordPress 丢弃未注册 handle 的内联配置。管理员只读诊断不暴露本地路径。v1 字段、schema 子集及消息合同见[教学扩展接口](TEACHING-EXTENSIONS.md)。

编辑器的参数草稿与已应用配置分离。候选未应用或无效时锁定原生保存和配对导出，选区切换仍保留；明确应用或撤销后才能继续。编辑画布只编辑静态正文，交互入口放在父文档的“教学配置”面板。静态 srcdoc 预览继续禁脚本，交互 iframe 使用独立 opaque sandbox、主插件前置 CSP、有界资源读取和会话／运行标识校验。具体算法与 Worker 不进入主插件。

同页最多四个预览、两个活动执行；较小的提供者预算继续约束资源、初始化、执行和完成摘要。关闭、隐藏阶段、配置变化、移除正文和页面离开清理旧实例，迟到消息不能覆盖新状态。扩展负责实际计算与轨迹限制；父窗只接受有界摘要，不能将客户端报告冒称完整安全沙箱或独立证明。所有播放、输入和输出均为临时阅读状态，静态正文、全文、打印与无脚本不依赖执行成功。

## 差异与冲突交互

编辑桥使用按行比较和唯一行锚点划分修改片段，小范围使用有界 LCS，大范围重复内容按替换展示。每片段首批最多 200 行，首批最多 20 个片段，后续由用户展开，避免长文一次生成大量 DOM。

预览和保存发生版本冲突时，保留候选并锁定编辑字段，提供 Markdown 下载和服务器最新版比较。来源文章须同时读取匹配的文章指纹与源文件指纹；读取失败或期间再次变化时禁止采用新基线。用户明确选择保留候选并继续后，必须重新预览才能保存。不自动合并、不绕过服务端校验。默认不将候选存入浏览器持久存储；2.0 开发候选的显式本地恢复另遵循下节约束。关闭弹窗后丢弃迟到异步结果。

### 浏览器恢复候选（2.0 开发中）

恢复是浏览器侧候选副本，不是第二份服务端正文。只在明确启用后记录有界表单／区块快照，使用站点、用户、文档及来源身份、权限摘要和原基线；不持久化 nonce、cookie 或服务器路径。共享 localStorage 的索引与记录通过 Web Locks 串行更新，sessionStorage 标签身份配合实例锁隔离，停用世代阻止迟到校验复活记录。无法取得可靠锁时拒绝启用。

每次列出、读取、恢复和写入前通过只读恢复上下文重新鉴权。权限／来源不匹配不能应用；旧内容基线保留用于显式冲突核对。恢复只进入已有转换、预览与确认链，未托管的新区块必须先证明精确可表示，再由真实转换后端重新校验首次配对创建。原生保存清理须以实际保存的快照为准，不能用请求成功推断当前所有输入均已保存。TTL、JSON 字节预算、失败及用户清除是可观测状态，不提供加密或永久存储承诺。

## 正文任务列表

简单普通列表继续使用 `core/list`。含任务（包括嵌套任务）的列表使用 `mbb/list`，普通项为 `mbb/list-item`，任务项为 `mbb/task-item`；后者保存 `content` 与布尔 `checked`，后续块保留为 innerBlocks。持久化 HTML 使用安全文字标记而不保存 input；区块渲染阶段仅为任务项生成禁用复选框。正文不再泛化替换普通文字标记，评论仍沿用原规则。

服务端 allowlist 接受新块但不放宽 KSES。旧复杂任务文字快照通过历史解析器的完整序列化精确比对恢复；私有 worker 的 `paired_restore` 同时接收历史 Markdown 与区块，REST 不增加对应公开模式。来源身份、指纹、权限、修订验证保持原路径。编辑后的内容仍须严格往返；不静默忽略属性或转换不支持的块。

## 脚注

命名引用由 `span.mbb-footnote-ref[data-mbb-footnote]` 保留名称及原始标记，编辑器注册独立 RichText 格式。唯一的顶层 `mbb/footnotes` 位于文末，包含 `mbb/footnote{label}` 与正文 InnerBlocks；定义顺序保留，显示编号不进入存储。脚注解析使用锁定的 markdown-it-footnote，在其搬移定义前检查重复、孤儿、非法名称及嵌套引用，避免默认解析行为静默丢弃内容。

服务端通过正常 KSES 和区块 allowlist 处理这些安全标签，不存储 input 或可执行内容。`mbb_render_footnotes` 在前台与 REST 预览共同生成按首次引用排序的编号、文档作用域唯一锚点及每次引用的返回链接；跳过代码/链接中的伪标记，重复渲染保持幂等。前台不引入写入接口。

编辑桥 srcdoc 预览显式内联受信脚注 CSS，将片段链接指向 `about:srcdoc`，避免 iframe 点击脚注时错误加载父页面。脚注引用工具栏按完整标记边界改名，不把相邻引用一并替换。

旧解析器只用于完整源/区块快照精确匹配的兼容恢复；新导入仍执行严格脚注引用完整性检查。未改变文章身份、来源绑定、权限、冲突检测及配对保存/修订流程。

## PHP 转换架构（1.3.0）

1.3.0 新安装默认 PHP，已有非空 Node 目录配置保持 Node，依据配置选择而非转换失败后回退。后端常量优先并锁定选择，其次新数据库配置，仅缺失时按旧目录推断；存在但损坏的新配置明确拒绝。`MARKBRIDGE_RUNTIME` 常量只优先覆盖 Node 路径，不锁定引擎。管理员后台通过专用 nonce 和 `manage_options` 验证并应用选择；PHP 保留有效 Node 目录供切回。`mbb_convert()` 统一分派，原有权限、来源绑定、指纹、修订与事务层不变。后端错误不自动重试另一引擎。

PHP 的单一实现位于 `plugin/includes/php-converter/`，Worker 适配 Markdown 导入、区块反转、精确配对恢复及批处理协议。未编辑的已验证历史配对保留原文和快照，编辑后的区块需真实反转再验证。依赖在构建阶段按 Composer 锁文件安装并通过固定 PHP-Scoper 隔离命名空间，随包携带；不与其他插件共享 Composer 加载器。摘要或私有命名空间冲突检查失败即拒绝转换。当前准入限定 PHP 8.2+、DOM/mbstring 和 WordPress 7.1.x 模板，仍有 256 KiB 文档边界及明确语法拒绝差异。

保存链、依赖隔离、干净安装、升级／回退及管理员双引擎选择已通过限定本地验收。实际环境、安装包检查与未覆盖范围见[验证说明](VALIDATION.md)，已完成的阶段记录见[归档架构计划](plans/completed/PORTABLE-CONVERTER.md)。

## 界面语言（2.0 候选）

英文 msgid 与 `plugin/languages/messages.json` 的中文译文共同生成 POT、PO、MO 和稳定脚本 handle 的 JSON。编辑器、管理员和 REST 可读提示采用用户语言，前台阅读控件采用站点语言；纯 PHP／Node 转换器始终返回英文诊断、原错误码与位置，在展示边界按已登记的 `message_id`／`message_args` 翻译。未知诊断、正文片段或路径不进入译文插值，使用通用失败提示；没有匹配翻译时回到英文。

翻译入口验证占位符，包含 HTML 的译文必须保留原标签、属性及片段边界；输出仍按所在的文本、属性或 URL 上下文转义。`mbb-i18n` 一次加载完整脚本目录，其他 handle 的 JSON 只补目录元数据，避免重复下载；构建检查实际调用、确定性输出与目录摘要。

语言不进入 Markdown、区块保存 HTML、参数、登记摘要或版本指纹。为精确兼容旧配对，既有固定默认标题、代码组保存说明、静态待应用占位及受信模板文字继续保留，不因界面语言迁移；作者可以正常编辑自己的标题。公式隔离文档仅接受闭合的英文／中文界面选择。受信教学提供者必须显式声明 `supportsUiLocale` 才收到新增的初始化语言字段；旧 v1 提供者仍收到原来的闭合消息，语言不写入组件参数或执行状态。

## 管理员显示设置

`plugin/includes/admin-settings.php` 通过 WordPress Options API 保存单一 `markbridge_display_preferences` 选项。只有具备 `manage_options` 的账号通过专用 nonce 才能提交，四个字段按固定枚举／布尔值校验；未知字段、缺失字段或错误类型拒绝，读取损坏值按字段回到默认但不自动回写数据库。

源码字号只传给 Markdown 输入框；公式阅读开关只控制前台阅读交互；代码行号／复制开关控制对应 Prism 资源及展示，保留高亮和语言标签。设置不参与转换、文章保存、修订或来源协议。显示选项、转换方案、旧运行目录及图片包选项保持独立；服务器常量优先级和旧配置升级兼容仍保留，后台转换方案不会提供关闭保存保护的选项。
