# 私有配对备份接口

适用于 2.6.0-rc.1 隔离候选。备份是未正式提交的候选，独立于正文、WordPress 修订、附件和来源文件；原生自动保存保护保持启用。作者入口见[编辑与保存](USAGE.md#服务端配对备份)。

## 身份与权限

`/wp-json/mbb/v1/paired-backups` 仅供登录账号使用，Cookie 认证时须带有效 `X-WP-Nonce`。每次请求重查文章编辑权限、托管身份、来源绑定和账号权限。仅已有托管文章可备份，新草稿继续使用本机恢复。不同账号即使都能编辑同篇文章，也不能读取对方备份正文。

`context` 复用 `recovery-context` 的站点、账号、文章、来源身份、权限与原基线指纹。`expected` 仍是当前正式文章的保存指纹；文件来源还带来源摘要。备份不提高权限，不授权来源写回，不提供公开下载地址。

## 请求与响应

| 方法          | 请求                                                                                                                       | 结果                                                                                                                             |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| GET           | `post_id`                                                                                                                  | 当前 `context`、本人该文章的 `items` 元数据和正式 `saved` UTC 时间；无备份正文                                                   |
| POST 创建     | `post_id`、当前 `context`、原 `expected`、`mode:markdown/blocks`、`source/serialized`、`title`、`status`、`featured_media` | 服务器执行正常候选、组件／HTML／媒体验证及完整配对恢复校验，复查原基线后保存私有快照；返回元数据列表                             |
| POST 准备恢复 | `post_id`、`key`、当前 `context`                                                                                           | 原记录（含两种表示、原 `context` 和输入 payload），另附 `currentContext`、`recordBaseline`、`currentBaseline`、`stale`；不写正文 |
| DELETE        | `post_id`、`key`                                                                                                           | 仅删除本人该文章对应备份；返回剩余元数据                                                                                         |

`key` 是服务器生成的不可预测选项标识，不能代替对象权限。列表只含键、时间、表示类型及基线。输入不接受资源 ZIP、资源收据、FrontMatter 应用选择或新原生区块导入旁路；尚未准备好的资源与配置保留在现有编辑器／本机恢复中。

准备恢复用请求的当前基线做 CAS。旧记录原基线保持不变，浏览器明确采用其候选与当前正文做差异预览；没有原签名基线时不声称三方合并。准备后再次发生文章、来源或权限变化会拒绝应用。文件来源摘要与原备份不同会直接拒绝准备恢复，先按原来源工作流核对。

恢复后的正式保存仍须正常 `/preview` 和明确 `/save`，沿用 `expected`、来源摘要、来源写回确认及完整事务保护。无效输入、超额、到期、失效登录、缺权限或存储失败返回错误，不能标为已备份；当前输入保持在编辑器中。

## 存储、并发和保留

每份记录存为独立非自动加载的私有 WordPress option，小索引记录所有者、文章、时间、字节及基线；不建立公开附件或文件。默认每账号／文章最近 10 份、最长 7 天，全站正文记录最多 32 MiB、4096 份。策略只清理本模块备份，不操作正式修订。全站空间不足时失败并保留旧恢复点；为新正文预留配额，再写新记录，成功后才回收该账号／文章的旧项。恢复中断的预留和超数记录随下次请求有界收敛。

正常备份请求惰性清理到期项，不新增 cron。清理只覆盖索引登记的本模块记录。短暂同时保留替换前后记录时，仍要求全站总字节有足够空间，不以预计删除量透支预算。

专用 WordPress MySQL 连接持有连接级 `GET_LOCK`，并禁止断线自动重连和 SQL 重放；连接断开即失败，进程结束释放锁。锁内清除索引和负缓存，避免长请求旧缓存覆盖另一请求的索引。多站点沿用基础表前缀和当前 blog ID。仅支持 WordPress 原生 `wpdb`，存在自定义数据库 drop-in／路由时明确拒绝备份，常规编辑继续可用。新连接沿用 WordPress 的数据库配置、字符集和 TLS 客户端设置。

编辑器在停止输入 30 秒后尝试自动备份，尝试间隔至少一分钟。关闭本页开关、离开页面或后续输入会撤销本页等待与迟到结果；已经提交到服务器的请求可能完成，但不会因此自动恢复或保存正文。取消开关不删除已完成记录；可逐份删除。服务端保留期与本机恢复开关相互独立。站点数据库备份可包含这些私有 option，诊断不得导出备份正文。

## 验证入口

`php tests/paired-backups.php` 检查配额、保留、失效指纹、权限重查、旧负缓存与断线写失败模型。`tests/paired-backups-save.php` 必须通过显式标识的本地 WordPress 合成站运行，覆盖真实 REST、配对转换、正文不变及权限。`tests/browser/paired-backups.spec.cjs` 检查浏览器时序、错误、取消与保存票据；模拟 REST 不能替代实际 Cookie／nonce、数据库和来源文件验收。
