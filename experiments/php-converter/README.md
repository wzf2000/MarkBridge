# PHP 转换隔离实验

这是“免额外运行环境”架构计划的独立原型，不是可安装插件，不被现有插件加载，也不在发行源码白名单中。当前保存链与正式版本不变。完整阶段见[架构改进计划](../../docs/plans/active/PORTABLE-CONVERTER.md)。

## 复现

需要 PHP 8.2+、DOM、mbstring。Composer 仅用于开发时安装锁定依赖；未来若采用此架构，生产依赖应随发行包附带，安装者不运行 Composer。

```sh
composer install --working-dir=experiments/php-converter --no-interaction --no-plugins --no-scripts
printf '%s' '{"mode":"markdown","source":"# Hello\n\nText **here**.\n"}' \
  | php -d disable_functions=exec,shell_exec,system,passthru,proc_open,popen,pcntl_exec \
    experiments/php-converter/cli.php
python3 -m unittest discover -s experiments/php-converter -p 'test_*.py'
```

CLI 只从标准输入读取一个 JSON 请求。`mode=markdown` 使用 `source`；`mode=blocks` 使用 `serialized`；`mode=paired_restore` 使用 `source`、`serialized` 和非空 `documentId`，返回精确配对及 `snapshot_kind`。成功返回 `ok/source/serialized`，Markdown 导入额外返回 `normalized_source`：`source` 保留原文，规范化结果来自真正的区块逆向解析。区块模式不接收也不缓存原 Markdown。失败返回 `ok=false/code/message`。

与现有引擎对照，需要一个匹配当前构建的隔离测试运行环境（只在测试侧使用 Node，不是 PHP 的依赖）：

```sh
python3 experiments/php-converter/compare.py --runtime /path/to/matching-test-runtime
```

脚本核对转换内核指纹，生成被 Git 忽略的 `results-comparison.json`。每个样例分别检查 PHP 自身往返、Node 接受 PHP 区块、PHP 反转 Node 区块及两边规范区块一致性。每个样例都有接受/拒绝预期；必要功能缺失、共同支持样例的区块字节或双向规范结果不同，以及历史配对契约不符都会失败。运行前后核对 PHP 实现和样例指纹，避免测试期间改动混入证据。Node 使用现有批处理接口，仅减少测试环境重复启动。

## 设计选择

- 锁定 `league/commonmark` 2.10.3，以 AST 遍历实现受限区块转换。公式与任务标记在解析器扩展中识别，保留引用/列表容器、代码与转义边界，不用全文正则代替语法解析。
- 服务器原型使用 PHP DOM 做区块逆转，并重新生成检查。DOM 解析错误（包括重复属性）、未知属性/节点、危险 URL 和无法保留的结构直接拒绝。
- 实验使用独立受限区块注释解析器；尚未用 WordPress PHP parser 替换或证明对全部 Gutenberg 合法输入兼容。
- WordPress 区块输出适配当前明确结构；不是任意第三方区块转换器。模板维护、核心升级与规范变更仍需持续适配。
- 原文、规范化原文及区块分别上限 256 KiB，节点上限 10,000，深度上限 32；JSON 请求另有限额。生成输出同样检查上限，不能导入成功后因区块膨胀而无法再反转。脚注引用在解析期间计数，HTML 上下文增量扫描；其余部分检查仍在 AST 解析之后。这些是原型边界，不代表现有插件容量、所有输入的 CPU 硬限或全面拒绝服务审计。

## 已确认的兼容边界

已适配标题、段落、强调、删除线、链接、图片、表格、代码、引用、普通与嵌套列表、任务列表、命名脚注、行内和行间公式、`more` 及受限 HTML。具体通过样例和有意拒绝见下面第二阶段契约；不是任意 HTML 或全部第三方区块支持承诺。

未知区块、额外样式、事件属性和不匹配区块结构拒绝，不静默删改。危险 Markdown 链接主动拒绝；现有 Node 引擎可能将相同输入保留为字面文字，属于尚未统一的策略差异。

原始 Markdown 与规范化 Markdown 不是同一承诺：未使用的链接定义、排版空白等可只保留在原始 `source`；从修改后的区块重建时不能恢复全部原文拼写。精确历史配对恢复已有独立接口，不能用它替代真实编辑反转；最小改写及保存层接入尚未实现。

任务标记必须按原始语法识别。转义/实体编码的 `[x]` 是普通列表；标记后直接软换行的行为以现有引擎为基准，不能把另一解析库的默认行为视为插件契约。正文软换行需要与现有引擎的 `breaks` 策略一致。

## 第二阶段契约（隔离验证完成）

本阶段适配 1.2.0 已有内容类型，不新增 Markdown 语法，不改保存接口或数据库。测试输入固定在 `fixtures.json`，每项显式列出 PHP 和 Node 应接受/拒绝的结果；未实现的必要功能会让测试失败。三类有意收紧的边界单独标记，不能与双方都拒绝的输入混算：

- 危险 Markdown URL：PHP 明确拒绝，现有引擎可能显示为字面文本。
- 公式或字面实体作为图片替代文本：现有引擎可能丢失公式，或把字面 `&copy;` 再次解码为字符；PHP 不为字节相同复现这种丢失。普通 `A & B` 不受此限制。
- 重复 HTML 属性：PHP 拒绝，不允许 DOM 修复把重复属性隐藏。

恢复与编辑是两个契约：`paired_restore` 必须从所给原文用当前或明确支持的旧规则重新生成区块，与所给快照逐字节匹配后才返回原配对；它不等同于能通过今天的编辑逆向校验。无意义的原文尾部空行可生成同一快照，但区块快照的额外空白不能忽略。文档 ID 必须非空；对象权限、身份归属、来源绑定、并发版本和写入事务仍由后续保存层检查，转换器本身不提供保存授权。

`blocks` 则必须读取提交的实际区块，反转再重建，不能返回请求中的缓存原文。属性类型、公式源码与显示文本、脚注引用/定义、表格结构和嵌套都参与校验；无法表达的编辑明确拒绝。历史恢复的宽容路径不能用于普通编辑。

独立区块注释解析器仅接受已知序列化子集；当前 Node/WordPress 对照是适配基准，不代表第三方区块或所有 Gutenberg 合法变体均已支持。现有 256 KiB、10,000 节点、32 层上限也是原型的明确限制，与现有服务器的输入容量不等价；进入保存链前必须统一容量政策和错误提示。

## 第二阶段验证结果

2026-10-08 完成固定合成矩阵与独立审查，结论是：**当前契约下的 PHP 转换候选可以进入保存链集成，不代表已完成可安装替换。**

| 检查                        | 实际结果                                                                                                                |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 89 个源样例                 | PHP 接受 66、拒绝 23；Node 接受 70、拒绝 19；全部符合逐例显式预期                                                       |
| 66 个共同支持样例           | 区块逐字节一致；PHP 自身往返、Node 接受 PHP 区块、PHP 反转 Node 区块后的规范结果均一致                                  |
| 7 份历史配对、49 项变化检查 | 精确配对与等价原文共 14 项接受并保留原配对；35 项改源/改块/空 ID/额外区块空白按预期拒绝；PHP 与 Node 结果一致           |
| 17 项测试方法               | 全部通过，包含源矩阵、图片/表格/脚注实际修改反转、缓存原文不可替代反转、属性/结构拒绝、历史恢复及资源组                 |
| 9 组资源样例                | 禁用 PHP 子进程、128 MiB 内存、测试侧每次 5 秒超时；未超时或崩溃，成功输入额外独立反转再导入通过                        |
| 环境与一致性                | PHP 8.2.32，WordPress 7.1 / Node 24.21.0 对照，内核与当前构建匹配；测试前后 PHP 与样例指纹一致；格式和 PHP 语法检查通过 |

4 个 PHP 拒绝而 Node 接受的样例属于上述 3 类有意收紧策略：危险 URL、公式图片替代文本、字面实体图片替代文本、重复 HTML 属性。其余 19 个拒绝样例双方都拒绝。不是 89 个输入都应成功，也不以“拒绝更多”宣称无兼容影响。

历史矩阵包含旧脚注字面量、旧复杂任务列表、新任务/旧脚注混合，以及当前普通编辑反转会拒绝但精确恢复应接受的表格快照。验证的是重新生成的完整快照一致，不是凭缓存或信任任意客户端 HTML 恢复。

资源组包括 256 KiB 边界、250 KiB 长美元前缀、深引用、6,000 段落、稀疏宽表格、18,000 次脚注引用和大量分隔符。最终本机单次启动加导入约 90–512 ms；18,000 次引用明确 `STRUCTURE_LIMIT`，不再反复全量扫描已有兄弟节点。256 KiB 原文若生成区块或规范原文超限也拒绝，替代第一阶段仅检查输入、可能接受后无法独立反转的行为。测量不代表持续负载、所有恶意组合或其他机器上限。

审查发现并修复实体二次解码、HTML 内公式保护、图片/链接脚注边界、生成输出上限不一致及脚注扫描退化。额外图片替代文字的既有丢失行为选择明确拒绝，未仿照旧引擎制造内容变化。

仍需在后续阶段完成：统一生产输入容量与错误提示，评估上述拒绝策略对已有配对和迁移的影响，接入 REST/原生保存/修订/来源写回/CLI，验证权限与事务，扩展 WordPress/PHP 矩阵、真实编辑器与无 Node 干净安装，再进行升级、灰度和协调回退。本轮没有改生产版本、真实文章或设置，也没有创建发行包。

## 第一阶段结论（历史基线）

2026-10-08 本地验证结论：**受限子集的真实 PHP 双向转换可行，值得进入完整适配；目前不能替换现有引擎。**

| 检查              | 实际结果                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------- |
| 22 个合成源样例   | PHP 接受 15 个、明确拒绝 7 个；现有 Node 接受 19 个                                                                 |
| 15 个共同支持样例 | 输出区块逐字节相同；PHP 自身往返、Node 接受 PHP 区块与 PHP 反转 Node 区块后规范结果均一致                           |
| 9 项专门断言测试  | 全部通过，涵盖真实区块编辑反转、属性/结构拒绝、危险输入、限制、未实现功能、转义任务、续行行为、原文保留与代码字面量 |
| PHP 执行环境      | PHP 8.2.32，测试时禁用 exec/shell_exec/system/passthru/proc_open/popen/pcntl_exec；不加载 WordPress、不访问数据库   |
| 对照环境          | WordPress 7.1 / Node 24.21.0，内核 SHA-256 与当前 1.2.0 构建一致                                                    |
| 依赖检查          | 锁定 CommonMark 2.10.3，Composer audit 无已知公告或废弃包                                                           |

PHP 拒绝而 Node 接受的 4 个源样例分别为脚注、表格、图片和危险链接（Node 将该链接作为字面文本处理）。另外 3 个双方拒绝样例为脚本 HTML、重复脚注定义、缺失脚注定义。不能把 15 个支持样例通过描述为 22 个全部兼容。

本机单次 PHP CLI 启动加转换约 112–140 ms（该批小样例）；额外 256 KiB 未闭合美元前缀约 158 ms，40 层引用及 6,000 个段落分别以结构上限拒绝。额外检查使用 128 MiB PHP 内存上限和测试侧 5 秒超时。这些是局部合成测量，不代表持续负载、所有恶意输入或生产容量。

独立审查发现并修复了转义/实体任务误判、重复 HTML 属性被 DOM 吞掉、美元扫描平方级耗时；最终还对齐了软/硬换行与标记后续行的现有引擎行为。此阶段只证明继续投入有依据，不构成默认后端切换或无 Node WordPress 安装验收。

这是第一阶段结束时的范围；新增语法、历史恢复和边界修复以第二阶段结果为准。WordPress/PHP 版本矩阵、保存/权限/事务/来源链集成、真实编辑器验证、无 Node 干净安装、更多资源攻击检查、升级和协调回退仍未完成。
